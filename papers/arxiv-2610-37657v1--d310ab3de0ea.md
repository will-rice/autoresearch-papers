# Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness

###### Abstract

We introduce Heads of Security (HoS), a prompt injection defense that
enforces instruction–data separation via a small set of learned per-head
attention gates. HoS learns how each head should redistribute attention
between trusted and untrusted tokens, enabling models to reason over
untrusted content without following injected instructions. We evaluate
HoS on Llama-3.3-70B-Instruct and GPT-OSS-20B. We compare it against
SecAlign++, a state-of-the-art finetuning-based defense, and ASIDE, a
defense that, like ours, builds instruction–data separation into the
model architecture. We show that HoS offers greater robustness to
adaptive attacks, better performance on standard utility benchmarks, and
matches top performance on standard agentic prompt injection benchmarks.
More specifically, the black-box RL-Hammer attack reaches 97% ASR
against GPT-OSS-20B and 85% against SecAlign, but only 10% against HoS.
Claudini, a state-of-the-art white-box attack, strengthened against HoS
through autoresearch, requires $`3\times`$ more FLOPs to reach the same
ASR on HoS as it does on GPT-OSS-20B or SecAlign. HoS preserves
base-model utility across standard multiple-choice benchmarks and
prompting setups, whereas SecAlign and ASIDE degrade in few-shot
settings. On agentic benchmarks with static attacks, HoS and SecAlign
perform similarly and substantially improve the security–utility
trade-off over the base model. ASIDE struggles with tool use, achieving
only 10% utility. These results show that prompt injection robustness
can be achieved and improved through targeted attention interventions.

### 1 Introduction

Indirect prompt injection ([Greshake et al., 2023](#bib.bib67)) occurs
when a model mistakes attacker-planted instructions in external content
for authorized commands. As LLMs access more external data and tools,
this attack surface becomes increasingly consequential. Although
frontier models have become substantially harder to attack ([UK AI
Security Institute, 2025](#bib.bib3)), prompt injection remains largely
unsolved: adaptive attacks continue to succeed even against extensively
evaluated systems ([Nasr et al., 2026](#bib.bib37); [Andriushchenko et
al., 2025](#bib.bib4)). This is more pronounced for open-weight models:
under comparable red-teaming, Claude and GPT are substantially more
robust than leading open-weight models ([Dziemian et al.,
2026](#bib.bib1)).

Defending against prompt injection requires several complementary
mechanisms. We focus on instruction–data separation ([Zverev et al.,
2025](#bib.bib30)), which creates a hard trust boundary: authorized
instructions may steer model actions, while external data may be read
and analyzed but not treated as instructions. Instruction–data
separation applies when external content is intended as data, for
example, when summarizing a webpage or extracting facts from a document.
It complements other approaches such as instruction hierarchy ([Wallace
et al., 2024](#bib.bib27)) and contextual integrity ([Nissenbaum,
2004](#bib.bib35); [Mireshghallah et al., 2024](#bib.bib36); [Abdelnabi
and Bagdasarian, 2026](#bib.bib33)) by preventing attacks when a hard
trust boundary exists.

We propose Heads of Security (HoS), which enforces instruction–data
separation via a small set of learned per-head attention gates. These
gates redistribute attention between trusted and untrusted tokens,
enabling models to reason over untrusted content without following
injected instructions.

HoS relies on two intuitions. First, previous interpretability works
have shown that attention heads specialize in different functions,
including in-context copying ([Elhage et al., 2021](#bib.bib42)), copy
suppression ([McDougall et al., 2024](#bib.bib44)), and instruction
following ([Hung et al., 2025](#bib.bib38)). This suggests that each
head can learn its own redistribution of attention between trusted and
untrusted content, specific to that head’s role, and that untrusted
instructions can be suppressed without disrupting unrelated
capabilities. Second, the trust boundary is supplied externally (e.g.,
web results are usually treated as untrusted), so enforcing it does not
require the model to infer which sources are trusted or to acquire any
new capabilities. Instead, it is an attention-routing problem:
controlling how information from trusted and untrusted sources reaches
the model’s existing capabilities.

We compare HoS against two defenses. SecAlign++ ([Chen et al.,
2025c](#bib.bib29)) is a state-of-the-art finetuning-based defense whose
Meta-SecAlign-70B checkpoint is considered among the most adversarially
robust open-weight models. ASIDE ([Zverev et al., 2026](#bib.bib32)) is
an architectural defense that enforces instruction–data separation by
rotating the embeddings of untrusted content.

We evaluate HoS on two open-weight models:
Llama-3.3-70B-Instruct ([Grattafiori et al., 2024](#bib.bib5)) and
GPT-OSS-20B ([Agarwal et al., 2025](#bib.bib2)). The former is a capable
agentic model and the base model of Meta-SecAlign-70B, enabling direct
comparison with SecAlign¹¹ 1 For brevity, throughout this paper we use
“SecAlign” to refer to the SecAlign++ training recipe.. GPT-OSS-20B is a
newer, smaller mixture-of-experts reasoning model that has generally
stronger capabilities than Llama-3.3-70B and has been post-trained to
enforce instruction hierarchy.

Compared to both SecAlign and ASIDE, HoS offers greater robustness to
adaptive attacks, better performance on standard utility benchmarks, and
matches top performance on standard agentic prompt injection benchmarks.

Greater robustness to adaptive attacks
([Section 4.1](#S4.SS1 "4.1 Adaptive attacks ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")).
Using black-box RL-based attacks trained with the RL-Hammer recipe ([Wen
et al., 2025b](#bib.bib8)), the strongest attackers reach 97% attack
success rate (ASR) on GPT-OSS-20B, 85% on SecAlign, but only 10% on HoS.
Similar results hold for Llama-3.3-70B: the strongest attacker reaches
99% ASR against the undefended model and 82% ASR against
Meta-SecAlign-70B but only 1% ASR against HoS. In a white-box setting, a
state-of-the-art optimization-based attack, Claudini ([Panfilov et al.,
2026](#bib.bib57)), further optimized specifically against HoS in an
autoresearch loop, still requires roughly $`3\times`$ more compute to
reach 50% ASR on HoS compared to GPT-OSS-20B and its SecAlign variant.

Preserving utility on standard benchmarks
([Section 4.2](#S4.SS2 "4.2 Benign utility ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")).
Across standard multiple-choice benchmarks and prompting setups, HoS
closely matches both base models. SecAlign and ASIDE match base-model
performance in 0-shot evaluations but often struggle in few-shot and
multi-turn settings. On 5-shot MMLU-Pro, HoS scores 67% versus
GPT-OSS-20B’s 68%, while SecAlign and ASIDE fall to 59% and 52%; on
Llama-3.3-70B, HoS scores 55% versus the base model’s 56%, while
SecAlign falls to 16%
([Table 2](#S4.T2 "In 4.2 Benign utility ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")).

Strong utility and security on agentic benchmarks
([Section 4.3](#S4.SS3 "4.3 Agentic prompt injection benchmarks ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness"),
[Appendix G](#A7 "Appendix G Prompt-injection benchmark details and full results ‣ Appendix ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")).
On AgentDojo, AgentDyn, LLMail-Inject, and WASP, HoS and SecAlign
perform comparably across both base models, substantially reducing ASR
with little or no utility penalty in most evaluations
([Figure 4](#S4.F4 "In 4.3 Agentic prompt injection benchmarks ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness"), [Table 3](#S4.T3 "In 4.3 Agentic prompt injection benchmarks ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")).
On the other hand, ASIDE consistently fails to produce usable tool
calls, scoring near-zero utility on three benchmarks and only 10% on
AgentDojo.

We also investigate what gates HoS learns mechanistically, using causal
head ablations and role-confusion probes
([Section 5](#S5 "5 Analyzing the learned attention gates ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")).
Together, these results establish attention gating as a targeted and
efficient approach to instruction–data separation.

### 2 Related work

Prompt injection defenses. Various types of defenses have been proposed
for instruction–data separation. Meta-SecAlign ([Chen et al.,
2025c](#bib.bib29)), our strongest baseline, is a finetuning-based
method ([Chen et al., 2025a](#bib.bib25); [Chen et al.,
2025b](#bib.bib28); [Chen et al., 2025c](#bib.bib29)) that uses
DPO ([Rafailov et al., 2023](#bib.bib14)) to teach models to follow user
instructions while ignoring injections in data. Architectural methods
directly encode input roles: Instructional Segment Embedding adds
learned role embeddings to token embeddings ([Wu et al.,
2025a](#bib.bib31)), while ASIDE applies fixed rotations to data-token
embeddings ([Zverev et al., 2026](#bib.bib32)). Our method, Heads of
Security, also enforces instruction–data separation architecturally, but
through reweighting attention according to token trust levels.

Attention and prompt injection. Recent work suggests that the attention
mechanism is directly related to instruction following. PASTA ([Zhang et
al., 2024](#bib.bib53)) and InstABoost ([Guardieiro et al.,
2025](#bib.bib52)) steer attention toward selected text or instruction
tokens, while Causal Head Gating studies instruction-following
mechanisms by suppressing attention head outputs ([Nam et al.,
2025](#bib.bib47)). Under prompt injection, specific attention heads
shift their attention from the benign instruction to injected
instructions ([Hung et al., 2025](#bib.bib38); [Zhong et al.,
2026](#bib.bib41)). HoS builds on these observations: we allow each head
to learn its attention redistribution such that injected instructions
are ignored.

(Adaptive) attacks. Existing prompt injection defenses remain
vulnerable, especially against strong adaptive attackers ([Nasr et al.,
2026](#bib.bib37); [Wen et al., 2025b](#bib.bib8); [Yang et al.,
2025b](#bib.bib49); [Panfilov et al., 2026](#bib.bib57)).
RL-Hammer ([Wen et al., 2025b](#bib.bib8)), a black-box RL-based attack,
achieves ASRs of up to 92% against GPT-5-series models, 77% against
Claude Sonnet 4, and near-100% on Llama-3.3-70B-Instruct defended with
SecAlign ([Chen et al., 2025c](#bib.bib29)). This motivates our adaptive
attack evaluations using RL and white-box optimization-based attacks
developed by autoresearch ([Panfilov et al., 2026](#bib.bib57)).

### 3 Method

#### 3.1 Preliminaries

We consider a decoder-only language model ([Vaswani et al.,
2017](#bib.bib13)) consisting of $`L`$ transformer layers, each with
$`h`$ attention heads of dimension $`d_{h}`$. The model receives a
sequence of tokens $`t_{1},\ldots,t_{n}`$ and predicts a distribution
over the next token $`t_{n+1}`$. Head $`k`$ of layer $`\ell`$ projects
the residual stream representation to get a query vector
$`q\in\mathbb{R}^{d_{h}}`$ for the last token, and key and value
matrices $`K,V\in\mathbb{R}^{n\times d_{h}}`$ representing all $`n`$
tokens in a sequence.²² 2 For notational clarity we omit ($`k`$,
$`\ell`$) indices in per-head equations and omit the key–value sharing
used in grouped-query attention. We write the attention for the final
token only to skip causal masking. It then computes
$`\mathrm{Attn}=aV\in\mathbb{R}^{d_{h}}`$, where
$`a=\operatorname{softmax}(qK^{\!\top}/\sqrt{d_{h}})\in\mathbb{R}^{1\times n}`$
is the vector of attention weights the final token pays to each position
in the sequence. More generally, we write $`a^{(\ell,k)}_{ij}`$ for the
attention that position $`i`$ pays to position $`j`$.

We assign each token $`t_{j}`$ a channel $`c_{j}`$ from
$`\mathcal{C}=\{{\color[rgb]{0.1055,0.4961,0.2305}\textsc{trusted}},\;{\color[rgb]{0.7539,0.2227,0.168}\textsc{untrusted}},\;{\color[rgb]{0.125,0.3945,0.6914}\textsc{template}}\}`$,
representing its trust level. In a typical setting, the trusted channel
covers the system and user prompts, as well as the model’s own
generation, while the untrusted channel is assigned to tool outputs. The
assignment is flexible and can represent more complex trust boundaries,
such as untrusted spans in the user prompt or trusted tools. The
template channel is assigned to chat-template tokens. Notably, these
include the BOS token, which usually acts as an attention sink ([Sun et
al., 2024](#bib.bib6); [Gu et al., 2025](#bib.bib7)). We use
$`C=|\mathcal{C}|`$ to denote the total number of channels.

#### 3.2 Channel-conditioned attention gates

HoS lets each head selectively reduce attention to a source channel. An
instruction-following head can be prevented from reading untrusted
content while retaining access to trusted instructions; other heads
remain free to process that content, preserving the model’s ability to
reason over it.

[Figure 1](#S1.F1 "In 1 Introduction ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")
illustrates this mechanism for a trusted user instruction and an
untrusted tool output. For clarity, the figure attributes instruction
following to a single idealized head, although in reality the behavior
is distributed across many heads and layers
([Section 5](#S5 "5 Analyzing the learned attention gates ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")).
In this example, the head initially assigns equally high scores to both
inputs. HoS closes its gate for the untrusted tokens, and softmax
renormalization places $`0.99`$ of its attention mass on the user’s
instruction.

HoS adds a learned, per-channel bias to each head’s pre-softmax
attention logits. Each head $`k`$ of layer $`\ell`$ has a table of gate
logits $`g^{(\ell,k)}\in\mathbb{R}^{C\times C}`$, where
$`g^{(\ell,k)}_{c_{i},c_{j}}`$ controls attention from query channel
$`c_{i}`$ to key channel $`c_{j}`$. We write
$`\theta_{\text{gate}}=\{g^{(\ell,k)}\}_{\ell,k}`$ for the full set of
gate logits that HoS trains for a model. For the token at position
$`n`$, the gated attention at layer $`\ell`$ and head $`k`$ is

|     |

````math
\mathrm{HoS}=\tilde{a}V\in\mathbb{R}^{d_{h}},\qquad\tilde{a}=\operatorname{softmax}\!\left(\frac{qK^{\!\top}}{\sqrt{d_{h}}}\;+\;\biggl\{\log\sigma\bigl(g_{c_{n},c_{j}}\bigr)\biggr\}_{\!j=1}^{\,n}\right)\in\mathbb{R}^{1\times n}.
``` |  | (1) |

Here $`\sigma`$ denotes the logistic sigmoid, so $`\sigma(g)\in(0,1)`$
scales each head’s attention to different channels: near 1 means the
head attends normally to that channel, near 0 means the gate is closed.
Inside the softmax, each attention logit is exponentiated before the
resulting weights are normalized. Adding $`\log\sigma(g)`$ to a logit
therefore multiplies its unnormalized attention weight by
$`\exp(\log\sigma(g))=\sigma(g)`$. This is the same mechanism used for
causal masking: adding $`-\infty`$ to a disallowed token makes its
exponentiated weight zero. If every key receives the same gate, softmax
cancels the common shift, so only differences between gates affect the
output. The absolute scale of the initial logits is therefore
irrelevant, and an input whose tokens all share one channel is processed
exactly as in the base model.

The formulation above applies directly to Llama-3.3. GPT-OSS requires a
slight modification because it includes an explicit attention sink: we
treat the sink as an additional key-only channel, giving each head a
gate table $`g^{(\ell,k)}\in\mathbb{R}^{C\times(C+1)}`$. We give the
sink-aware definition in
[Appendix D](#A4 "Appendix D HoS with GPT-OSS attention sinks ‣ Appendix ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness").

#### 3.3 Training

HoS trains only $`|\theta_{\text{gate}}|=LC^{2}h`$ gate parameters. For
Llama-3.3-70B ($`L=80`$, $`h=64`$), this is $`46{,}080`$ scalars,
compared with 349M parameters for SecAlign and 70B for full-parameter
fine-tuning and ASIDE. GPT-OSS-20B adds one sink key channel, giving
$`|\theta_{\text{gate}}|=LC(C+1)h=18{,}432`$ scalars ($`L=24`$,
$`h=64`$), compared with 38M for SecAlign, and 21B for ASIDE.

We follow the SecAlign++ training recipe ([Chen et al.,
2025c](#bib.bib29)), including its Direct Preference Optimization
objective ([Rafailov et al., 2023](#bib.bib14)) and adapted
Cleaned-Alpaca dataset ([Ruebsamen, 2023](#bib.bib18)). Each preference
pair combines a user instruction with an injected instruction in the
untrusted segment; the preferred response follows the user instruction,
while the rejected response follows the injection. Full training details
are provided in
[Appendix J](#A10 "Appendix J Training setup ‣ Appendix ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness").

### 4 Results

#### 4.1 Adaptive attacks

RL-Hammer on InjecAgent (black-box). HoS is more robust to the
state-of-the-art black-box RL-Hammer attack than the undefended and
SecAlign models on both GPT-OSS-20B and Llama-3.3-70B. Strikingly, it
even achieves lower attack success rates than GPT-5.6-Luna. We follow
the original RL-Hammer setup ([Wen et al., 2025b](#bib.bib8)), using
GRPO ([Shao et al., 2024](#bib.bib62)) to train a Llama-3.1-8B-Instruct
attacker to rewrite an attacker goal into an injection optimized against
a particular target model. Each main target model is paired with the
same easy target model within its model family: undefended GPT-OSS-20B
at low reasoning effort for the GPT-OSS experiments, and
Llama-3.1-8B-Instruct for the Llama experiments. We additionally train
an attacker against GPT-5.6-Luna, paired with the same easy target as
the GPT-OSS attackers.

#### 4.2 Benign utility

Heads of Security largely preserve base-model utility across standard
question-answering and instruction-following benchmarks. In contrast,
SecAlign and ASIDE perform comparably to the base model in zero-shot
settings but degrade in several few-shot and multi-turn settings.

We hypothesize that these failures arise from broader fine-tuning on
narrow data. All three defenses use similar training data, based on
single-turn Alpaca data. Few-shot prompts and multi-turn conversations
fall outside these training formats. SecAlign’s LoRA updates and ASIDE’s
full fine-tuning may learn spurious correlations specific to those
formats, whereas HoS’s restricted attention-gating parameterization
preserves utility despite the narrow training distribution.

### 5 Analyzing the learned attention gates

In this section, we analyze why HoS works by showing that most heads
shift attention away from untrusted content, while a minority of heads
shift towards it and support prompt injection detection.

How is attention redistributed? We analyze the learned gates to
characterize how training redistributes attention and where the largest
shifts occur. For a given layer $`\ell`$ and head $`k`$, we quantify the
shift from untrusted to trusted keys as:
$`\Delta^{(\ell,k)}=\log\sigma\big(g^{(\ell,k)}_{{\color[rgb]{0.1055,0.4961,0.2305}\textsc{t}},{\color[rgb]{0.1055,0.4961,0.2305}\textsc{t}}}\big)-\log\sigma\big(g^{(\ell,k)}_{{\color[rgb]{0.1055,0.4961,0.2305}\textsc{t}},{\color[rgb]{0.7539,0.2227,0.168}\textsc{u}}}\big),`$
where
$`g^{(\ell,k)}_{{\color[rgb]{0.1055,0.4961,0.2305}\textsc{t}},{\color[rgb]{0.1055,0.4961,0.2305}\textsc{t}}}`$
and
$`g^{(\ell,k)}_{{\color[rgb]{0.1055,0.4961,0.2305}\textsc{t}},{\color[rgb]{0.7539,0.2227,0.168}\textsc{u}}}`$
are the gate logits from a trusted query to trusted and untrusted keys,
respectively.

Most values in
[Figure 2](#S4.F2 "In 4.1 Adaptive attacks ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")
(right) are positive, indicating that most heads reduce their relative
attention to untrusted keys. This is the expected direction for heads
involved in instruction following: reducing their access to untrusted
instructions should make the model less likely to follow them. A
minority of heads instead increase their relative attention to untrusted
content. We investigate these heads below.

Why do some gates increase attention to the untrusted region? Following
the colors in
[Figure 2](#S4.F2 "In 4.1 Adaptive attacks ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")
(right), we refer to heads that shift attention away from untrusted
content as *red* heads, and heads that shift attention toward untrusted
content as *blue* heads. We hypothesize that blue heads help *detect*
prompt injections. As [Abdelnabi and Bagdasarian (2026)](#bib.bib33)
argue, agents should both resist injected instructions and recognize
injection attempts.

Their benchmark uses a subset of LLMail-Inject to test whether agents
can summarize emails and flag injected instructions. We measure the
*send rate* (following an injection to send an email; lower is better)
and *detection rate* (correctly flagging the injection; higher is
better). To assess each group’s role, we evaluate “Red gates only” and
“Blue gates only” variants, disabling HoS gates on heads of the opposite
color.

All four models have send rates below 1%, but their detection rates
differ markedly
([Table 4](#S5.T4 "In 5 Analyzing the learned attention gates ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")).
Blue gates alone increase detection from 11.03% to 28.20%, roughly
$`2.5\times`$ the base rate, whereas red gates alone reduce it to 3.60%.
This supports our hypothesis that blue heads help detect prompt
injections. With all HoS gates enabled, the detection rate is 3.11%.

Role confusion. Recent work by [Ye et al. (2026)](#bib.bib24) argues for
viewing prompt injection through the lens of role confusion. According
to this framing, successful attacks hinder the model’s ability to
correctly attribute the source of the injected instruction. For example,
a malicious instruction in the untrusted tool output may be viewed by
the model as originating from the user, and thus be erroneously trusted.
How does HoS affect the perceived roles?

To test this, we adopt the role probes introduced by [Ye et al.
(2026)](#bib.bib24). Role probes are linear probes on hidden activations
that are trained on benign text with a neutral style, taken from the
pretraining corpus and embedded in role tags. Trained only on the tag
signal by construction, these probes were shown to correctly identify
the role of each part of the conversation in some scenarios. Further,
[Ye et al. (2026)](#bib.bib24) show that the Userness of the injected
instruction token span (that is, how much its tokens are perceived as
coming from the User role) is highly correlated with attack success
rate. We train the probes following the original recipe exactly. For
HoS, as in deployment, tool tokens are in the untrusted channel.

To observe the effect of HoS on the perceived roles, we test GPT-OSS-20B
and its HoS variant on AgentDojo. First, using AgentDojo benign user
tasks, we measure the accuracy (fraction of correctly classified tokens
in a given role) for User and Tool roles, since confusion of those two
roles is relevant for indirect prompt injection attacks. Further, on the
attacked version of AgentDojo, we compute the Userness of the injection
token spans, which was shown to predict attack success rate in simple
scenarios ([Ye et al., 2026](#bib.bib24)).

We report the observations in
[Figure 5](#S5.F5 "In 5 Analyzing the learned attention gates ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness").
First, we find that HoS significantly improves the role perception for
the tool outputs, compared to the base model. Second, we find that HoS
decreases the perceived Userness of the injection tokens in the attacked
AgentDojo scenarios.

Overall, these results suggest that among other effects, the HoS
mechanism improves the model’s role perception for the roles relevant to
indirect prompt injection attacks. Viewed through the lens of role
confusion, this provides additional evidence that better role perception
correlates with prompt injection robustness.

### 6 Discussion and Limitations

Instruction–data separation is not an end-to-end defense. HoS enforces a
trust boundary, but it does not decide which sources are trusted or
which instructions the user has authorized. Moreover, some tasks
legitimately require following instructions from external content, such
as installing a software package. Strict instruction–data separation
therefore applies only when that content is intended merely as data to
process. We view it as one primitive in a broader defense, complementing
instruction hierarchy ([Wallace et al., 2024](#bib.bib27)), which orders
instructions by source, and contextual integrity ([Mireshghallah et al.,
2024](#bib.bib36)), which captures context-sensitive authorization.

Training data is fixed. We train HoS and SecAlign on the same preference
dataset to isolate the effect of the training algorithm. More diverse
data, including multi-turn conversations, multiple instructions, and
varied templates, would likely improve both methods and may mitigate
SecAlign’s out-of-distribution failures. We do not claim these failures
are inevitable. However, on identical data, SecAlign learns a shortcut,
while HoS does not. Our claim is therefore that constraining the
learning mechanism reduces its capacity to acquire unintended biases
from the training distribution.

The attacker moves second. Attackers can adapt their methods after
seeing a defense, so no finite evaluation can establish security ([Nasr
et al., 2026](#bib.bib37)). However, evaluated under the same attack
budget, RL-Hammer and Claudini are less successful against HoS. This
suggests that HoS is harder to attack than baselines, but does not rule
out a successful attack by a motivated and capable adversary.

HoS is designed for standard dense attention. Our method applies
per-channel biases to pairwise attention logits before the softmax. It
is therefore not directly compatible with linear attention
architectures ([Yang et al., 2024](#bib.bib55); [Yang et al.,
2025a](#bib.bib54)) where there is no explicit coefficient representing
the attention to a specific key token. Extending the same trust
constraint to pure linear attention architectures would require a
different gating mechanism.

Conclusion. We introduce Heads of Security (HoS), a targeted
intervention that enforces instruction–data separation by redistributing
attention between trusted and untrusted tokens on a per-head basis. For
the open-weight models we test, HoS is more robust to adaptive attacks
and better at preserving utility outside the training distribution,
while matching or improving SecAlign’s security–utility trade-off. These
results show that instruction–data separation can be enforced by
constraining attention rather than broadly fine-tuning model behavior.

## Appendix

### Appendix A Additional related work

Prompt injection vulnerability and defenses. Prompt injection remains a
major security problem for LLM applications, ranking first in OWASP Top
10 LLM security risks since 2024 ([OWASP Foundation, 2024a](#bib.bib21);
[OWASP Foundation, 2024b](#bib.bib22); [OWASP Foundation,
2026](#bib.bib23)). Indirect prompt injection occurs when an attacker
places instructions in external content and induces the model to follow
them. As LLMs increasingly gain access to external data and tools, this
attack surface becomes more consequential. Recent defenses aim to ensure
that models follow authorized instructions from trusted sources while
resisting malicious instructions in untrusted content. Instruction
hierarchy ([Wallace et al., 2024](#bib.bib27)) prioritizes instructions
by source, allowing the model to follow lower-priority instructions in
external content only when they align with higher-priority ones in the
user prompt. Instruction–data separation imposes a stricter constraint
on content designated as data: the model may read and reason over it but
must not follow instructions embedded within it ([Zverev et al.,
2025](#bib.bib30)). For example, a model summarizing a webpage should
describe its contents without following any embedded instructions.
Enforcing this boundary is challenging because models can mistake
untrusted content for user instructions through role confusion ([Ye et
al., 2026](#bib.bib24)). Some workflows, however, require following
instructions from external content, such as skill files ([Schmotz et
al., 2026](#bib.bib34)), and deciding which instructions should be
followed is a context-dependent problem studied through contextual
integrity ([Abdelnabi and Bagdasarian, 2026](#bib.bib33)). HoS focuses
on improving prompt injection robustness in settings with a defined
instruction–data boundary.

Unlike defenses that strengthen the underlying model,
CaMeL ([Debenedetti et al., 2025](#bib.bib26)) is a system-level defense
that enforces security policies on tool calls and information flows even
if the underlying model remains vulnerable, but it does not defend
against prompt injection attacks that only affect the target model’s
text output (e.g., biasing the summary of a webpage).

Attention head specialization. Existing literature shows that attention
heads often develop narrow and well-defined purposes. A small subset of
heads is important for translation ([Voita et al., 2019](#bib.bib46));
induction heads copy token sequences that previously appeared in
context ([Elhage et al., 2021](#bib.bib42)); 26 heads are responsible
for indirect-object identification in GPT-2 small ([Wang et al.,
2023](#bib.bib43)); copy-suppression heads suppress naive in-context
copying to improve next-token prediction ([McDougall et al.,
2024](#bib.bib44)); and retrieval heads recover relevant information
from long contexts ([Wu et al., 2025b](#bib.bib45)).

Recent work suggests that instruction following similarly relies on
specialized attention mechanisms. PASTA ([Zhang et al.,
2024](#bib.bib53)) reweights attention from a small subset of heads so
that they pay more attention to user-specified parts of the prompt,
while InstABoost ([Guardieiro et al., 2025](#bib.bib52)) strengthens
instruction following by directly increasing attention to instruction
tokens. Relatedly, Causal Head Gating ([Nam et al., 2025](#bib.bib47))
identifies a separable head-level circuit for instruction following that
can be disabled while largely preserving other capabilities.

Attention and adversarial instructions. Beyond general head
specialization, prior work has linked attention directly to adversarial
instruction following. [Xue et al. (2025)](#bib.bib51) show that
adversarial prompts can subvert rule-based inference by suppressing
attention to legitimate rules. Related work on jailbreaks shows that
GCG ([Zou et al., 2023](#bib.bib20)) suffixes can hijack model
contextualization, and that suppressing attention components involved in
this mechanism can mitigate such attacks ([Ben-Tov et al.,
2026](#bib.bib50)), while [Yin et al. (2026)](#bib.bib48) show that
jailbreaks can suppress a small set of safety-relevant heads.

Under prompt injection, specific attention heads shift their attention
from the benign instruction to the malicious instruction embedded in the
data part ([Hung et al., 2025](#bib.bib38); [Zhong et al.,
2026](#bib.bib41)). Relatedly, residual stream activations can
distinguish inputs containing injected instructions ([Abdelnabi et al.,
2025a](#bib.bib39)) or act as features for a prompt injection
detector ([Wen et al., 2025a](#bib.bib40)).

HoS builds upon these observations: by conditioning each head’s gate on
the query and key channels, we allow attention heads responsible for
instruction following to learn to operate normally on trusted input
while restricting how they attend to untrusted input.

Llama’s largest shifts cluster in middle and late layers. The heatmap

layers 40–70. Larger shifts cluster around layers 15–40, with another

### Appendix C Uniform suppression of untrusted tokens

Figure 7: Uniform suppression does not match the security–utility
trade-off of learned gates. GPT-OSS-20B on (a) AgentDojo and (b)
AgentDyn. Purple triangles vary a single untrained gate logit for

Uniform suppression does not match HoS’s security–utility trade-off. We
test whether reducing attention to untrusted content uniformly is
sufficient to obtain the benefits of learned gates. We replace the
learned gates with a single untrained logit $`u`$ for untrusted keys,
shared across all heads, layers, and query channels. Trusted, template,
and attention-sink gate logits are fixed at zero, so $`u=0`$ leaves
attention unchanged.
[Figure 7](#A3.F7 "In Appendix C Uniform suppression of untrusted tokens ‣ Appendix ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")
shows $`u\in\{-4,-3,-2,-1,0\}`$ alongside HoS models from the
learning-rate sweep in
[Table 13](#A7.T13 "In G.2 Full GPT-OSS-20B trade-off results ‣ Appendix G Prompt-injection benchmark details and full results ‣ Appendix ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness").

On AgentDojo, $`u=-2`$ achieves 60.8% utility under attack but still has
11.1% ASR, whereas HoS achieves 59.6% utility at 1.1% ASR. Stronger
uniform suppression ($`u=-3`$) approaches this ASR at 1.5%, but utility
falls to 50.8%. The same pattern holds on AgentDyn: $`u=-2`$ achieves
50.5% utility at 24.3% ASR, compared with 50.2% utility at 8.9% ASR for
HoS. At $`u=-3`$, uniform suppression reduces ASR to 5.0% while utility
falls to 31.6%; HoS achieves both lower ASR (3.9%) and higher utility
(45.9%). At the strongest uniform suppression setting ($`u=-4`$), ASR
falls below 0.4% on both benchmarks, but utility drops to 22.6% on
AgentDojo and 2.7% on AgentDyn. These results show that per-head
learning of the gates is important for maintaining the security–utility
trade-off.

### Appendix D HoS with GPT-OSS attention sinks

GPT-OSS appends a learned scalar sink logit $`s^{(\ell,k)}`$ to each
head’s content logits before the softmax. This is a pretrained model
parameter that remains frozen during HoS training; the additional sink
gate is trainable. The probability assigned to the sink is discarded
before the attention weights are multiplied by $`V`$, without
renormalizing the remaining weights, allowing a head to place
probability mass on no content token.

For a query at position $`n`$, let
$`\tilde{a}^{+}\in\mathbb{R}^{1\times(n+1)}`$ denote the distribution
over the $`n`$ content tokens and the sink. Let
$`m_{n}^{(\ell)}\in\{0,-\infty\}^{1\times n}`$ be the layer’s attention
mask, with $`-\infty`$ for keys outside the permitted attention window.
We extend the gate table with a key-only sink channel and compute

|  |  |  |  |  |
|----|----|----|----|----|
|  | $`\displaystyle\tilde{a}^{+}`$ | $`\displaystyle=\operatorname{softmax}\!\left(\left[\frac{qK^{\!\top}}{\sqrt{d_{h}}}+m_{n}^{(\ell)}+\biggl\{\log\sigma\bigl(g^{(\ell,k)}_{c_{n},c_{j}}\bigr)\biggr\}_{j=1}^{n}\;\middle|\;s^{(\ell,k)}+\log\sigma\bigl(g^{(\ell,k)}_{c_{n},\mathrm{sink}}\bigr)\right]\right),`$ |  | (2) |
|  | $`\displaystyle\mathrm{HoS}`$ | $`\displaystyle=\tilde{a}^{+}_{1:n}V.`$ |  |  |

The sink can appear only as a key, so the resulting table has shape
$`C\times(C+1)`$ rather than $`(C+1)\times(C+1)`$. In the
implementation, the final column is stored separately as one sink gate
per query channel and head; this is equivalent to the table above.

Gating the sink preserves the uniform-gate no-op property described in
[Section 3.2](#S3.SS2 "3.2 Channel-conditioned attention gates ‣ 3 Method ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness").
Adding the same bias to all content logits but not the sink changes the
allocation of attention between content and sink. If the sink receives
that same bias, all $`n+1`$ logits share a common shift, which softmax
cancels in exact arithmetic. This holds at initialization because
content and sink gates start at the same value. After training, even an
input whose tokens all share one channel can change the output if that
channel’s gate differs from the sink gate. Sliding-window layers use the
same formulation with out-of-window content keys masked; the sink
remains available independently of the window.

#### E.2 SecAlign on InjecAgent

Prompt layout and scoring substantially affect the measured InjecAgent
ASR. Our native-tool protocol gives 5% ASR for Meta-SecAlign-70B and 16%

The agent prompt, user task, previous assistant tool call, and tool

the attacker’s tool.

The SecAlign evaluation harness ([Chen et al., 2025c](#bib.bib29))
reports 0.5% ASR on InjecAgent. Here we investigate the difference. The
SecAlign harness uses InjecAgent’s ReAct text format. With instruction
hierarchy enabled, one input message contains the tool definitions, user
task, and full Thought/Action/Action Input/Observation scratchpad.

input role, affecting the model’s ability to call tools.

Its default setup also appends a reminder of the user’s task (the
“sandwich” defense). The ReAct parser classifies outputs as successful,
valid but unsuccessful, or invalid; ASR over all cases counts invalid
outputs as attack failures. The released model-card evaluation
additionally uses 1,054 direct-harm and data-stealing cases and reports
the higher ASR of the basic and enhanced settings, whereas our primary
evaluation uses 100 held-out direct-harm cases.

### Appendix F White-box attacks

###### Evaluation set.

We start from the 921 AgentDojo user-task–injection-task pairs used in
[Table 13](#A7.T13 "In G.2 Full GPT-OSS-20B trade-off results ‣ Appendix G Prompt-injection benchmark details and full results ‣ Appendix ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")
and retain the 675 pairs on which the fixed important_instructions
attack fails against all three target models. We further restrict the
pool to pairs whose injected goal is achievable with a single tool call
and whose prompt fits the attack’s memory bounds, leaving 187
candidates. The 100-pair evaluation set fills a per-injection-task quota
over this pool (six or seven pairs per injection task, seed 0). It
covers all 20 achievable injection tasks and 40 distinct user tasks: 48
banking, 33 workspace, 13 Slack, and 6 travel pairs.

###### Attack.

We use V38, the strongest substantive method found by the Claudini
autoresearch run described below ([Panfilov et al., 2026](#bib.bib57)).
It optimizes a 120-token suffix appended to the injection. Its
continuous branch combines adaptive dense-to-sparse constrained
optimization (ADC) ([Hu et al., 2024](#bib.bib58)) with layer-wise
gradual momentum (LSGM) ([Li et al., 2024](#bib.bib59)); it periodically
rounds the relaxation to discrete tokens and refines promising hard
suffixes by local search. The attack uses eight restarts and seed 0 and
retains the best suffix found so far, making it an anytime attack. Its
target is the injected task’s tool-call sequence in GPT-OSS’s native
Harmony format.

Every target model receives the same budget of $`10^{17}`$
active-parameter FLOPs per pair. The FLOP calculation for white-box
attacks follows [Boreiko et al. (2025)](#bib.bib60). Success is measured
end to end: we decode the suffix, render it again through the model’s
chat template, generate greedily, execute the resulting tool trajectory,
and apply AgentDojo’s deterministic security() predicate. Curves in
[Figure 2](#S4.F2 "In 4.1 Adaptive attacks ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")
(left) replay every stored best-so-far suffix through this pipeline.
“Delivered” reports the suffix that the anytime attack would return at
budget $`F`$; “cumulative” counts a pair as broken if any best-so-far
suffix up to $`F`$ succeeds.

###### InjecAgent evaluation.

We also evaluate V38 on the same 100 held-out InjecAgent ([Zhan et al.,
2024](#bib.bib61)) goals used for RL-Hammer, with a 120-token suffix,
eight restarts, seed 0, and $`10^{17}`$ active-parameter FLOPs per
example and target model. The attack optimizes the official
metric_minimal target. After re-rendering the suffix and generating
greedily, the InjecAgent scorer marks success when the first tool call
is the attacker’s tool; invalid outputs count as failures. At the full
budget, cumulative ASR is 95%, 100%, and 90% for the base, SecAlign, and
HoS models, respectively, as plotted in
[Figure 2](#S4.F2 "In 4.1 Adaptive attacks ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")
(left). The corresponding delivered ASRs are 90%, 100%, and 84%.

#### F.1 Autoresearch attack discovery with Claudini

We developed the attack against HoS through a Claudini autoresearch
loop ([Panfilov et al., 2026](#bib.bib57)) driven by GPT-5.6-Sol. Sol
edited the optimizer source directly, and each run optimized a separate
suffix per behaviour rather than one universal suffix. We seeded it with
Claudini’s optimizer library: GCG, PRS, and the stronger kimi_v45
continuous optimizer, which combines eight relaxed-token restarts, ADC
sparsification, and LSGM gradient scaling. kimi_v45 became the parent of
the branch that succeeded.

##### F.1.1 Autoresearch protocol

Sol’s task was to break HoS-defended GPT-OSS-20B; everything that would
instead let it break the comparison was frozen, namely the six
development behaviours, the model and HoS checkpoint, the seed, the
suffix length, the target construction, the compute budget, the prompt
renderer, and the success test. Inside that envelope it could read
anything: model weights, gate values, optimizer source, gradients, and
every previous transcript and loss. We asked it to keep a research log
and to keep proposing mechanistically distinct optimizers rather than
tuning one. It never saw the 100-pair evaluation set, which we used
once, after selection.

Each trial ran the proposed method on all six behaviours (samples 0–4
and 14) at seed 0, with a 120-token suffix and $`10^{17}`$
active-parameter FLOPs per behaviour; the six runs went out in parallel.
The prompt was a complete AgentDojo turn — system message and tool
schema, the user’s benign task, the assistant’s first tool call, and
that call’s YAML output — with the injection and the optimized suffix
occupying the injected field of that output, where HoS labels them
untrusted. The target was the behaviour’s attacker tool call in
GPT-OSS’s native Harmony syntax, function name and full JSON arguments,
with nothing prepended to steer generation into it.

The optimizer minimized full-target cross-entropy, but cross-entropy is
not the claim. After each run we decoded the suffix to text, re-rendered
the prompt around it, generated greedily, and executed whatever call
AgentDojo parsed out. ASR, the fraction of the six that executed the
attacker’s call, decided which optimizer came next; mean cross-entropy
only separated trials that executed nothing.

The loop produced 50 implemented trials (V1–V32 and V34–V51; V33 was
never implemented), one point each in
[Figure 8](#A6.F8 "In F.1.2 The selected V38 optimizer ‣ F.1 Autoresearch attack discovery with Claudini ‣ Appendix F White-box attacks ‣ Appendix ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness").
We selected V38 from this trajectory and evaluated it once on the
separate 100-pair set in
[Figure 2](#S4.F2 "In 4.1 Adaptive attacks ‣ 4 Results ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness")
(left).

##### F.1.2 The selected V38 optimizer

V38 extends V34. Its continuous branch combines the batched relaxed
token distributions and adaptive sparsity of ADC ([Hu et al.,
2024](#bib.bib58)) with the backward scaling of LSGM ([Li et al.,
2024](#bib.bib59)). V34 evaluates the hard projection from all eight
restarts, rejects suffixes that fail the contextual round-trip check,
and, after prolonged stagnation, samples one- and two-token alternatives
from the soft support. V38 retains this search and adds a persistent
archive and budgeted hard-token refinement:

- •
  Persistent feasible archive. Across optimization steps, V38 retains
  the four distinct round-trip-stable suffixes with lowest loss. When
  budget permits, four neutral, round-trip-stable strings seed the
  archive.
- •
  First-order hard proposals. Every 16 steps, V38 selects an archive
  suffix and differentiates full-target loss with respect to its
  hard-token embeddings. It ranks replacing $`x_{\ell}`$ with $`v`$ by
  $`\Delta_{\ell,v}=\mathbf{g}_{\ell}^{\top}(\mathbf{E}_{v}-\mathbf{E}_{x_{\ell}})`$.
  It forms the four best substitutions at each of the eight most
  promising positions, rejects round-trip failures, and scores the rest.
- •
  Persistent descent. The best improving child becomes the next parent;
  if none improves, refinement rotates to another archive member. The
  continuous ADC state and random-number stream remain unchanged.
- •
  Physical compute accounting. All hard-gradient passes and candidate
  evaluations count against the global budget. A refinement round runs
  only if its conservative cost bound fits the remaining budget and
  keeps cumulative refinement below 10% of charged FLOPs.

All V38 loss evaluations use the deployed HoS forward computation,

its direct parent V34, from $`2/6`$ to $`3/6`$. We therefore select V38
for the 100-pair evaluation.

### Appendix G Prompt-injection benchmark details and full results

#### G.1 Benchmarks and metrics

###### AgentDojo and AgentDyn.

We run both benchmarks through the AgentDojo harness, using the
VLLM_PARSED format for GPT-OSS-20B and LOCAL for Llama-3.3-70B. Across
all models and defenses, we impose a 12,288-token limit on the full
trajectory and allow at most 8,192 generated tokens in any single model
call. If either limit is exceeded, the trajectory is terminated and both
the user task and the injected task are scored as failed.

We exclude tasks that can exceed the context limit on the base model.
For GPT-OSS-20B, we exclude Workspace user tasks 35 and 38 from
AgentDojo; for Llama-3.3-70B, we exclude Workspace user tasks 26, 27,
34, 35, and 38. We exclude no tasks from AgentDyn.

AgentDojo ([Debenedetti et al., 2024](#bib.bib15)) pairs legitimate user
tasks with injected tasks in tool outputs across four environments:
Workspace, Slack, Banking, and Travel. AgentDyn uses the same harness
for three additional environments: Shopping, GitHub, and Daily Life. We
evaluate both with the important_instructions attack. Utility is the
fraction of legitimate user tasks completed, and attack success rate
(ASR) is the fraction of trajectories in which the injected task is
completed; both are determined by deterministic checks of the final
environment state. Clean utility is measured without an injection,
whereas utility under attack is averaged over user-task–injection-task
combinations.

For HoS, every tool-output token is assigned to the untrusted channel.
For SecAlign, we follow the authors’ evaluation strategy: tool outputs
are escaped and remapped to the input role, marking them as data rather
than instructions.

###### WASP.

WASP ([Evtimov et al., 2026](#bib.bib16)) evaluates a browsing agent on
webpages containing goal-hijacking injections. Its clean-utility set
contains 37 tasks, and its security set contains 84 combinations of user
tasks, injection tasks, and injection formats (plain text injection and
URL injection) across Reddit and GitLab environments. Following [Chen et
al. (2025c)](#bib.bib29), we represent webpages as accessibility trees
(hierarchical text descriptions of their relevant elements) and use a
24K-token context window.

Most elements in WASP webpages are fixed browser interface elements that
cannot be modified by users or prompt injection attackers, such as
buttons to post comments on Reddit and GitLab. For HoS and ASIDE, we
treat these tokens as trusted while treating all elements that could
have user-generated content, such as GitLab issue titles and
descriptions, Reddit post content, and URLs, as untrusted.

###### LLMail-Inject.

LLMail-Inject ([Abdelnabi et al., 2025b](#bib.bib17)) consists of
adaptive, human-written injections submitted to a public challenge. The
model acts as an email assistant asked to summarize retrieved emails,
while the attack attempts to make it call send_email to contact the
attacker. We evaluate a random sample of 4,000 Phase-1 submissions, with
1,000 drawn from each of the four challenge levels. The benchmark
natively measures only whether the attack succeeds. We additionally
measure utility under attack with Claude Sonnet 5, counting a response
as successful when it thematically covers every task-relevant email,
even if the summary appears inside a fabricated tool call.

Each HoS layer has a gate tensor of shape $`3\times 3\times 64`$,
corresponding to query channel, key channel, and attention head. GPT-OSS
has 24 layers and an additional $`3\times 64`$ sink-gate tensor per
layer, giving 18,432 parameters in total. Llama has 80 layers and no
explicit sink gate, giving 46,080 parameters. Gate logits are
initialized to 1, so each sigmoid gate initially equals
$`\sigma(1)=0.731`$. Because every channel pair begins with the same
value, this initialization is a no-op under softmax; GPT-OSS’s sink is
gated separately to preserve this property. We apply no explicit gate
regularization.

For our GPT-OSS SecAlign baseline, LoRA uses rank 64, $`\alpha=8`$, zero
dropout, and no bias on the attention $`q`$ and $`v`$ projections. The
mixture-of-experts gate_up_proj and down_proj tensors are adapted at
rank 2. The released Llama SecAlign adapter uses rank 32 and
$`\alpha=8`$, targeting the $`q`$, $`v`$, gate, up, and down
projections.

#### J.3 Preference data

Both model families use preference pairs derived from the synthetic
AlpacaFarm injection data used for SecAlign ([Chen et al.,
2025c](#bib.bib29)). For GPT-OSS, we additionally generate reasoning
traces for each preference option using GPT-OSS-120B.

#### J.4 Channel assignment

HoS uses three channels: trusted, untrusted, and template. System and
user content is trusted; content in the SecAlign input field is
untrusted; and chat-template tokens such as role headers belong to the
template channel. The model’s generated tokens are assigned to the
trusted channel. For GPT-OSS, the assistant’s final channel prefix is
kept outside the untrusted span.

The GPT-OSS SecAlign configuration instead renders the input field as
its own delimited header turn, following the SecAlign mechanism. Apart
from this placement of the untrusted span and the defense-specific
trainable parameters, the GPT-OSS HoS and SecAlign configurations use
the same optimization setup.

### Appendix K Full ASIDE results

In the main text, we report ASIDE ([Zverev et al., 2026](#bib.bib32)) as
one of the baselines. In the original formulation, ASIDE was proposed as
a full-finetuning method, trained on the benign Alpaca-clean-gpt4-turbo
dataset, without a reasoning turn, and treated the assistant response to
be data, and thus untrusted. Adapting ASIDE to reasoning models to be a
competitive baseline required several design choices. In this section we
report our search in this design space and list relevant training
hyperparameters.

###### Training data

We generate a reasoning version of the Alpaca-cleaned dataset by
replacing its answers with responses from a stronger teacher model,
GPT-OSS-120B, keeping the original instructions and input fields. The
targets include both reasoning and final answers. We use medium
reasoning effort, temperature 1 and top-$`p`$ 1. After filtering out
incomplete responses, we obtain 51,696 examples: 46,533 for training and
5,163 for validation. For adversarial training, we reuse the
reasoning-inclusive SecAlign preference corpus described in
[Appendix J](#A10 "Appendix J Training setup ‣ Appendix ‣ Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness"),
with 16,434 training and 1,826 validation pairs. DPO uses both
responses; SFT on this data uses only the preferred response to the
injected prompt.

###### Design choices

In making the original ASIDE formulation a competitive baseline, we
tried several alterations of the original formulation. We vary the
following things:

- •
  Training data: benign Alpaca data vs. SecAlign data.
- •
  Training method: SFT on benign data, DPO on SecAlign data, or SFT on
  the preferred SecAlign responses.
- •
  Full fine-tuning vs. LoRA adapters.
- •
  Which part of the input is untrusted: external input and tool outputs,
  or also assistant CoT, responses and tool calls, following the
  original ASIDE policy more closely.

###### Training and selection

All runs use AdamW, cosine learning-rate decay, no warmup, and zero
weight decay. Benign SFT uses loss on the full sequence, including the
prompt, with padding masked and gradient clipping at 1.0. It uses batch
size 256 and context length 9,216; LoRA runs use LR $`10^{-4}`$ for two
epochs, and full fine-tuning uses LR $`2\times 10^{-5}`$ for three
epochs. SecAlign-data runs use batch size 64, context length 4,096 and
three epochs, with no gradient clipping. Preferred-response SFT masks
prompt loss; DPO uses $`\beta=0.1`$. Their LoRA learning rates are
$`10^{-4}`$ and $`3\times 10^{-4}`$, respectively; both full-finetuning
runs use $`10^{-5}`$.

LoRA adapts query/value projections at rank 64 and expert gate/up and
down projections at rank 2, with $`\alpha=8`$, zero dropout and no
trainable biases. It trains on a frozen BF16-dequantized base;
evaluation uses the original MXFP4 base with adapters and per-module
scaling. Full fine-tuning uses FP32 master weights, BF16 computation and
four-GPU FSDP with microbatch size 1.
````
