###### Abstract

Language-model agents increasingly tackle long-horizon tasks whose
interaction histories exceed the model’s active context. They must
therefore decide what to write down and what to read back, and when to
do either. Recent work has begun to use on-policy distillation (OPD) to
make memory control part of the policy, relying on memory tools and
compaction protocols that lie outside either model’s pre-training.
However, this weakens the distillation on both sides: the teacher cannot
give useful guidance on an interface it has never used, and the student
samples too few meaningful memory actions for that guidance to take
effect. To study this problem, we introduce Coding Agent Memory Gym II
(CAMG-II), a suite of long-horizon agentic-RL environments spanning
Shop, Coding, AutoResearch, General, and Visual. Alongside each
environment’s native task interface, CAMG-II provides ordinary Bash
access and an episode-persistent workspace, enabling the policy to
create, revise, search, and reuse files as memory across context
replacements. We also introduce Coding Agent Memory Post-Training II
(CAMP-II), which trains a single policy jointly across all five
environments with fully asynchronous OPD to learn this file-based memory
behavior directly from a frozen teacher with a prior for file
operations. On CAMG-II, CAMP-II obtains 2.97 times the gain of the
strongest OPD baseline. The memory behavior CAMP-II learns generalizes
to two external benchmarks, Terminal-Bench 2.1 and SWE-Bench Pro V2,
with improved success rates.

## 1 Introduction

Language-model agents increasingly tackle long-horizon tasks that unfold
through repeated tool use and environment interaction
\[[65](#bib.bib65), [19](#bib.bib19)\]. As these interactions
accumulate, information needed for later decisions can fall out of the
model’s active context. A website-building agent, for example, may need
to recall why an earlier visual correction was rejected after that
exchange has left the prompt (Fig.
[1](#S0.F1 "Figure 1 ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")).

Recent work applies on-policy distillation (OPD) to memory control
through dedicated memory tools and compaction protocols
\[[79](#bib.bib79), [28](#bib.bib28), [34](#bib.bib34),
[27](#bib.bib27), [10](#bib.bib10)\]. However, this weakens the
distillation on both sides: the teacher cannot give useful guidance on
an interface it has never used, and the student samples too few
meaningful memory actions for that guidance to take effect
\[[13](#bib.bib13)\]. Moreover, unfamiliarity with the tool produces the
negative-advantage problem: the teacher’s scores push the student away
from the memory behavior being taught without indicating the behavior
that should take its place, which leaves training unstable
\[[16](#bib.bib16), [80](#bib.bib80)\]. This raises a question: can a
teacher teach a smaller model to control memory through operations that
both the teacher and the student already have a prior for?

To study this question, we introduce Coding Agent Memory Gym II
(CAMG-II), a suite of long-horizon agentic-RL environments spanning
Shop, Coding, AutoResearch, General, and Visual. Across all five
environments, CAMG-II pairs each native task interface with ordinary
Bash access and an episode-persistent workspace. Agents can therefore
create, revise, search, and reuse files as memory throughout an episode.

We also introduce Coding Agent Memory Post-Training II (CAMP-II), which
trains a single policy jointly across all five environments with fully
asynchronous OPD to learn this file-based memory behavior directly from
a frozen teacher with a prior for file operations. Task-reward training
of file-based memory asks one question, whether the student’s
pre-training prior makes the behavior reachable by exploration.
Distillation asks two. The student has to emit meaningful memory
operations, and the frozen teacher has to judge what those operations
write. A shared interface prior answers both at once. We train
CAMP-II-4B and CAMP-II-9B from Qwen3.5 models of matching size. On
CAMG-II, CAMP-II obtains 2.97 times the gain of the strongest OPD
baseline, and the memory behavior it learns generalizes to two external
benchmarks, Terminal-Bench 2.1 and SWE-Bench Pro V2, with improved
success rates.

Our contributions are threefold.

- •
  A two-sided interface prior for memory distillation. We identify what
  an interface has to provide for OPD to teach memory at all, coverage
  of the action on the student side and supervision quality on the
  teacher side, and we show that a shared file-operation prior supplies
  both.
- •
  An on-policy distillation method that uses it. We introduce CAMP-II,
  which learns this file-based memory behavior by on-policy distillation
  from a teacher that needs no memory-specific adaptation, and reaches
  the highest average success rate across the five test environments.
- •
  A long-horizon agentic-RL environment suite. We introduce CAMG-II with
  five environments that require memory across context boundaries, each
  pairing native task interfaces with ordinary Bash access and an
  episode-persistent workspace.

## 2 Related Work

##### Agentic RL for Memory.

These methods use reinforcement learning to improve how agents retain
and recover task information. Existing work optimizes state
consolidation and summary retention \[[86](#bib.bib86),
[26](#bib.bib26)\], while other approaches train agents to use dedicated
memory operations \[[79](#bib.bib79)\]. Context compaction is also
learned from downstream outcomes \[[28](#bib.bib28)\], and agents are
trained to manage their own context proactively through folding
\[[75](#bib.bib75)\]. Other work uses task rewards to train agents to
maintain state through ordinary filesystem actions, including bounded
continuation-file compression \[[37](#bib.bib37)\]. These methods spend
much of their exploration on invalid calls and failed executions
\[[10](#bib.bib10)\], which makes a denser target attractive. CAMP-II
also trains the policy, but the signal is token-level teacher targets
rather than task reward.

##### Memory Systems for LLM Agents.

These systems preserve interaction history under a bounded active
context through different representations and memory-management
architectures. Deployed frameworks give an agent persistent memory
outside its window: a long-term store maintained by an extraction and
update pipeline \[[6](#bib.bib6)\], hierarchical memory edited under an
operating-system abstraction \[[42](#bib.bib42)\], a note collection
that links and revises itself as the task proceeds \[[68](#bib.bib68)\],
and an interaction history organized as a temporal knowledge graph
\[[47](#bib.bib47)\]. All four are inference-time layers: the agent
queries a store that sits outside the weights, and the task policy
itself is never trained for the memory behavior. CAMP-II trains the task
policy itself, and its memory is kept in ordinary files that the teacher
can read as well.

##### On-Policy Distillation for Agent Memory.

OPD supervises student-generated prefixes with teacher predictions
\[[1](#bib.bib1)\]. For memory-dependent execution, existing approaches
reconstruct the compact-memory invocation state the student acted in
\[[34](#bib.bib34)\], annotate trajectories before distilling
\[[27](#bib.bib27)\], or train a separate memory controller or writer
through OPD followed by RL \[[30](#bib.bib30), [10](#bib.bib10)\]. Each
aligns the two models on the state or on the trajectory and leaves the
memory interface as given. That interface is a compact-invocation
protocol or a learned writer that neither model has practiced. CAMP-II
instead selects the interface from the prior the teacher and the student
share, and supervises memory content through it from a general teacher
without memory-specific adaptation.

## 3 Preliminaries

Multi-turn interaction. We consider finite-horizon, partially observable
tasks. Given the instruction and visible context $`h_{t}`$, the student
samples response $`a_{t}`$. The environment executes the response and
returns an observation for the next invocation. A trajectory $`\tau`$
contains $`T_{\tau}\leq H`$ invocations, where $`H`$ is the horizon.
Response $`a_{t}`$ contains $`L_{t}`$ tokens, and $`a_{t,<j}`$ is its
prefix before token $`j`$. Write $`s_{t,j}=(h_{t},a_{t,<j})`$ for the
context of that token prediction.

On-policy distillation. OPD trains on contexts and prefixes reached by
the student \[[1](#bib.bib1)\]. For a sampled token $`x`$ at prefix
$`s`$, let $`p_{\theta}(x\mid s)`$ and $`q(x\mid s)`$ be its
probabilities under the current student and frozen teacher. Sampling
from the student makes the reverse-KL gradient a policy gradient whose
per-token signal is the teacher–student log-ratio,

|     |     |     |     |
| --- | --- | --- | --- |
|     |

````math
\begin{split}A^{\mathrm{OPD}}_{\theta}(s,x)&=\operatorname{sg}\!\left[\log q(x\mid s)-\log p_{\theta}(x\mid s)\right],\\
\mathcal{L}_{\mathrm{PG}}(\theta)&=-\mathbb{E}_{(s,x)\sim\pi_{\theta}}\left[A^{\mathrm{OPD}}_{\theta}(s,x)\,\log p_{\theta}(x\mid s)\right].\end{split}
``` |  | (1) |

Here $`\operatorname{sg}`$ stops gradients through its argument.

## 4 Coding Agent Memory Gym II

To train agents to use files as memory, we construct CAMG-II as a suite
of five long-horizon environments (Fig.
[2](#S4.F2 "Figure 2 ‣ 4 Coding Agent Memory Gym II ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
that extends CAMG’s environments \[[37](#bib.bib37)\] with enterprise
knowledge work and visually grounded website development, drops
DeepResearch, an environment that is heavy to run and hard to optimize
with reinforcement learning, and refines the reward design and the tool
format. Each environment combines verifiable tasks with ordinary Bash
access and an episode-persistent workspace. Their tasks require agents
to reuse information accumulated earlier in the episode.

Every environment shares one interface. The workspace persists for the
whole episode and the active context does not: when the context
approaches its budget, it is cleared, so anything the next steps need
has to have been written down. Before that replacement the policy writes
a bounded continuation file carrying the task state, the replacement
proceeds once that write is valid, and the context that follows contains
only that file’s path. The state therefore survives a replacement when
the policy writes it and reads it back afterwards.

Figure 2: CAMP-II distils file-based memory across five environments.
Top: the student acts in the environment and writes and revises memory
files. At each context boundary it compresses its state into the

actually sampled, and the OPD learner updates the student weights from
the teacher–student log-probability gap, closing the loop back to the
rollout.

### 4.1 Constructing Five Long-Horizon Environments

##### Shop.

Shop tests whether an agent can retain customer requirements and earlier
purchase decisions across a sequence of dependent purchases. We generate
six-session tasks from 720 verified WebShop products
\[[74](#bib.bib74)\]. Between sessions the environment clears the active
session transcript, so later purchases depend on what the policy
retains.

##### Coding.

Coding tests whether an agent can complete a software repair whose
diagnosis, repository edits, and test evidence may span multiple active
contexts. We draw issue–repository pairs and test-defined repair
objectives from SWE-smith \[[70](#bib.bib70)\]. We exclude
non-executable tasks and those whose reference repairs fail their tests,
retaining 11,218 tasks from 93 repositories.

##### AutoResearch.

AutoResearch tests whether an agent can preserve hypotheses and
validation evidence across iterative model development. We use public
OpenMLE task packages with datasets, executable submissions, and native
metrics \[[71](#bib.bib71)\]. We exclude tasks that cannot run or whose
reference pipelines fail, retaining 931 tasks from 804 task families.

##### General.

General tests whether an agent can reconcile and retain evidence across
business documents and system interactions. We adapt MiMo’s enterprise
tasks \[[66](#bib.bib66)\], with rubric-based judging of the answer,
deliverables, and applicable system state. The adaptation also fixes
incomplete tool signatures by exposing all declared arguments and
distinguishing required from optional inputs.

##### Visual.

Visual tests whether an agent can retain design requirements and visual
inspection findings during website construction. We adapt MiMo’s website
briefs and visual grading \[[66](#bib.bib66)\]. The vision-capable agent
builds a static site, inspects rendered previews, and revises the
delivery. The delivered site receives an absolute rubric score for
visual quality, brief fulfillment, and asset quality.

### 4.2 A Shared File-Memory Interface

Across the five environments, CAMG-II standardizes an executable
filesystem interface for using files as memory while retaining each
environment’s native task interaction and outcome evaluation. Following
the minimal, shell-only interface of mini-swe-agent
\[[69](#bib.bib69)\], the shared filesystem action is a single bash
entry, which can create, inspect, search, modify, and execute files, so
the policy can preserve and revise task-relevant evidence and
intermediate state in the workspace. Let
$`\mathcal{A}_{d}^{\mathrm{task}}`$ denote environment $`d`$’s native
task-action set and $`\mathcal{A}^{\mathrm{fs}}`$ the shared
filesystem-action set. The CAMG-II action space is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{A}_{d}=\mathcal{A}_{d}^{\mathrm{task}}\cup\mathcal{A}^{\mathrm{fs}},\qquad a_{t}\in\mathcal{A}_{d}.
``` |  | (2) |

One bash entry can produce both native-task and filesystem effects, so
the two sets may overlap. Appendix
[A.2](#A1.SS2 "A.2 Shared Agent Interface ‣ Appendix A CAMG-II Environment Details ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")

traces one turn: at turn $`t`$ the student samples a response
$`a_{t}\sim\pi_{\theta}(\cdot\mid h_{t})`$ from the visible context
$`h_{t}`$, with $`a_{t}\in\mathcal{A}_{d}`$ as defined in Eq.
[2](#S4.E2 "Equation 2 ‣ 4.2 A Shared File-Memory Interface ‣ 4 Coding Agent Memory Gym II ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"),

response tokens across invocations and episodes, with $`x_{i}`$ the

$`p_{\theta,i}=\pi_{\theta}(x_{i}\mid s_{i})`$,
$`q_{i}=\pi_{T}(x_{i}\mid s_{i})`$, and
$`\mu_{i}=\pi_{\theta^{-}}(x_{i}\mid s_{i})`$ for the current student,

supervision as task tokens. After a context replacement only the path of
the file the student wrote earlier is supplied, and the student reads it
back to recover that state. The per-token signal is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
A_{i}^{\mathrm{OPD}}=\operatorname{sg}\!\left[\log q_{i}-\log p_{\theta,i}\right].
``` |  | (3) |

The rollout workers generate with the last published weights
$`\theta^{-}`$ while the learner updates $`\theta`$, so episodes from
all five environments reach the learner after later weights are
published. The update is corrected by the importance ratio
$`\rho_{i}=p_{\theta,i}/\mu_{i}`$, taken against the clipped value
$`\bar{\rho}_{i}=\operatorname{clip}(\rho_{i},1-\epsilon,1+\epsilon)`$.
Over the sampled response tokens $`\mathcal{B}^{m}`$ of an optimizer
minibatch, the objective is

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathcal{L}_{\mathrm{OPD}}^{m}(\theta)=-\frac{1}{|\mathcal{B}^{m}|}\sum_{i\in\mathcal{B}^{m}}\min\big\{\rho_{i}A_{i}^{\mathrm{OPD}},\;\bar{\rho}_{i}A_{i}^{\mathrm{OPD}}\big\},
``` |  | (4) |

## 6 Experiments

We first compare CAMP-II with baselines on the five-domain test set and
explain why file memory makes effective use of pre-training. We then
measure external transfer and ablate the content of a write. Finally, we
isolate the causal role of saved memory and follow one write from record
to readback.

### 6.1 Experimental Setup

##### Training.

All trainable methods use fresh Qwen3.5-4B and Qwen3.5-9B students
\[[46](#bib.bib46)\] for 100 learner optimizer updates with 64 episodes
per update, totaling 6,400 episodes per training run, under the equal
mixture over Shop, Coding, AutoResearch, General, and Visual, trained
with fully asynchronous OPD and no task rewards. Appendix
[C](#A3 "Appendix C CAMP-II Training Details ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
gives the remaining training details.

##### Baselines.

We compare against four trainable memory-learning systems: compact
memory with invocation reconstruction for MemOPD \[[34](#bib.bib34)\],
context editing and retrieval of offloaded history for ACM
\[[27](#bib.bib27)\], a hierarchical memory with provenance and validity
checks for HELM \[[30](#bib.bib30)\], and a separate writer with a
persistent bank for Hy-Memory \[[10](#bib.bib10)\]. For HELM we report
both the published architecture, which pairs a learned memory controller
with a separate task reasoner, and a single-model adaptation in which
one policy fills both roles. For MemOPD we report the recipe without and
with the paper’s SFT cold start. As the task-reward reference, we
additionally retrain the predecessor CAMP-I \[[37](#bib.bib37)\], which
keeps the same file memory and learns from task rewards instead of the
teacher’s supervision. Every system except CAMP-I is trained by common
reverse-KL OPD from the shared frozen Qwen3.8-27B teacher, so the
systems differ only in how they keep memory.

##### Ablations.

We compare CAMP-II with several variants to validate its components. The
variant compaction keeps its memory through the compaction protocol
instead of files. The variant memory tools keeps its memory through the
six dedicated tool calls instead of files. The variant gradient masked
removes the loss on the tokens the policy writes into memory and keeps
it on the task-action and answer tokens.

##### Evaluation.

We report per-domain success rates and their average, with the success
definitions in Appendix
[A](#A1 "Appendix A CAMG-II Environment Details ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation").
Trainable methods are trained using the CAMG-II train split and
evaluated using the CAMG-II test set, and all methods use the same 128
test tasks per domain, giving 640 tasks in total. We measure external
transfer on the network-free task subsets of Terminal-Bench 2.1 and
SWE-Bench Pro V2 \[[39](#bib.bib39), [7](#bib.bib7)\].

##### File-operation priors improve the task success of memory distillation.

To test whether file memory is the most task-friendly form of agent
memory, we compare CAMP-II against the baselines of Section
[6.1](#S6.SS1 "6.1 Experimental Setup ‣ 6 Experiments ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
(Table
[1](#S5.T1 "Table 1 ‣ 5 CAMP-II: File-Memory Distillation ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")).
CAMP-II attains the highest average success rate, 64.6% versus 54.2% for
CAMP-I, and the same comparison holds across five training seeds, where
the five-domain mean is 64.9 with a standard deviation of 0.5 (Table
[8](#A3.T8 "Table 8 ‣ C.3 Across training seeds ‣ Appendix C CAMP-II Training Details ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")),
and only two domains reach the frozen teacher’s level, Visual at 40.2%
against 40.3% and Shop at 100% for both. We attribute the margin to the
training signal: the teacher’s token-level targets supervise each memory
write as it is sampled, whereas CAMP-I must assign credit for memory
operations across the long horizon, and task-reward training, as [Fei et
al. \[10\]](#bib.bib10) analyze, spends much of its exploration on
invalid calls and failed executions.

The memory-learning baselines fall further behind, because their
channels are protocols the student must first learn, while CAMP-II’s is
ordinary file use. MemOPD shows what the protocol costs. Without its SFT
cold start it scores zero in every domain: the every-step memory rewrite
runs, but the student never submits a successful answer, and on-policy
distillation cannot supervise behavior that is never sampled. With the
cold start restored, MemOPD becomes the strongest memory-learning
baseline. HELM shows what separation costs: its published design puts a
learned memory controller in a second model, and the adaptation in which
one policy fills both roles gains 13.2 points, 49.8% against 36.6%.
Scaling the same recipe to a 9B student lifts the average to 66.5%,
closing 63% of the student–teacher gap. Appendix
[C](#A3 "Appendix C CAMP-II Training Details ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
reports training dynamics for CAMP-II and CAMP-I.

##### The teacher and the student pay least on the file interface.

To understand why training on the file interface works best, we test
whether that interface lies inside what the teacher and the student
already know. We measure how surprising the action each interface calls
for is to the frozen teacher and to the initial student, the mean
negative log-likelihood of the generated tokens in nats per token (Fig.
[3](#S5.F3 "Figure 3 ‣ 5 CAMP-II: File-Memory Distillation ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")a).
The file interface costs the teacher a third of what compaction costs
it, and the student a fifth, with the tool block in between. The teacher
pays more at every one of them, so a stronger model does not bring these
interfaces any closer. The interface also decides how finely the
teacher’s preference separates memory writes. Given two writes from one
interface and two task contexts, the teacher ranks the write that
carries the prefix’s own task above the foreign one in 76.5% of
decisions on the file interface, against 70.0% and 63.8% on the other
two. The ordering holds when the key information of a single note is
replaced by another task’s (Appendix
[D.3](#A4.SS3 "D.3 Teacher preference over memory content ‣ Appendix D Additional Experiments ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")).

##### The student reaches for memory most often on the file interface.

To see whether that prior also governs what the distillation has to work
with, we count the memory actions the student takes under each
interface. They are $`21.6\%`$ of all actions on the file interface,
against $`7.8\%`$ with the six dedicated tools and $`5.9\%`$ under
compaction (Fig.
[3](#S5.F3 "Figure 3 ‣ 5 CAMP-II: File-Memory Distillation ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")b).
The file interface is therefore the one interface where the teacher’s
target is cheapest and the student already emits the action it has to be
taught, which is why training there pays off. Appendix
[B](#A2 "Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
turns that coverage into the cost of teaching the action.

##### The negative advantage is strongest on the unfamiliar interfaces.

Once training runs, the per-token advantage can point either way. We
score the memory actions the student produces under each interface and
average the negative advantage, which roughly doubles from the file
interface to compaction, on interface decisions and on content tokens
alike (Fig.
[5](#S6.F5 "Figure 5 ‣ The student reaches for memory most often on the file interface. ‣ 6.2 Results ‣ 6 Experiments ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")).
The push against what the student wrote is therefore strongest where the
interface is least familiar, and it supplies no target to replace what
it removes. Prior work reports that a strong negative advantage
destabilises on-policy distillation \[[16](#bib.bib16),
[80](#bib.bib80)\].

##### The quality of the memory content determines task success.

To test whether the quality of the memory is what carries CAMP-II’s
gain, we intervene on it directly, and we also ablate the supervision
that reaches it. At the first context replacement we continue the same
episode three ways, with the memory it wrote, with another episode’s
memory, or with none of it, and nothing else differs between them (Fig.
[6](#S6.F6 "Figure 6 ‣ The quality of the memory content determines task success. ‣ 6.2 Results ‣ 6 Experiments ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")).
Success follows the content. The episode that keeps its own memory
completes the sequence, the one given another episode’s memory recovers
part of it, and the one whose memory is emptied recovers less. When we
mask the loss on the tokens the policy writes into memory and keep it on
the task-action and answer tokens, the gain from distillation largely
disappears (Fig.
[7](#S6.F7 "Figure 7 ‣ The quality of the memory content determines task success. ‣ 6.2 Results ‣ 6 Experiments ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")).
Masking the same number of tokens at random instead leaves it almost
intact, at 63.3 against 64.6, so the loss comes from the supervision on
memory content rather than from the smaller budget. The improvement
therefore lives in learning what to write into memory, which is what
CAMP-II trains.

To see which part of CAMP-II carries the gain, we ablate the memory

(Fig.

so the choice of interface decides most of the gain.

## 7 Conclusion

We investigate how the shared pre-training priors of teachers and
students affect memory-oriented on-policy distillation. Unlike
task-reward RL, memory OPD requires both a student that can generate
meaningful memory actions and a teacher that can provide reliable
supervision over their content. To study this two-sided requirement, we
introduce CAMG-II, a suite of five long-horizon agentic environments,
and CAMP-II, which trains one policy across them with fully asynchronous
OPD over ordinary file operations.

Our experiments show that the file interface improves both student
memory-action coverage and the teacher’s ability to distinguish
task-relevant memory content. Memory interventions and supervision
ablations further establish the role of learned memory content in
downstream task performance. CAMP-II achieves 2.97 times the gain of the
strongest OPD baseline on CAMG-II and generalizes to Terminal-Bench 2.1
and SWE-Bench Pro V2, where CAMP-II-9B outperforms the larger
Qwen3.5-35B-A3B on both benchmarks. Shared interface priors are
therefore a design consideration for memory OPD, complementary to
improving distillation objectives or teacher guidance.

##### Limitations.

The study covers students up to Qwen3.5-9B and a single frozen teacher.
Whether the gains persist at larger scales or carry over to
multi-teacher OPD remains untested.

## Appendix A CAMG-II Environment Details

CAMG-II contains five environments built around long-horizon tasks in
which information obtained early can matter after the active context is
replaced. Shop composes new multi-session tasks from WebShop products.
Coding, AutoResearch, General, and Visual select executable tasks from
SWE-smith, public OpenMLE task packages, and MiMo’s enterprise and
website collections, respectively \[[37](#bib.bib37), [70](#bib.bib70),
[66](#bib.bib66)\]. Each environment preserves its domain interaction
and definition of task success. CAMG-II adds a bounded active context
and an episode-private workspace that persists across context
replacement.

### A.1 Environment Construction

#### A.1.1 Shop

Shop turns six WebShop purchases into one episode \[[74](#bib.bib74)\].
A later request can depend on a preference, constraint, or clarification
established in an earlier session, so the policy must retain the
relevant customer state across browser resets. It builds on CAMG’s
verified catalog catalog and six-session task generator
\[[37](#bib.bib37)\]. Catalog admission checks unique normalized titles,
search reachability, product identifiers, attributes, and purchase
prices. The generator fixes a customer, request sequence, candidate
order, dependency branch, and total budget so that exactly one
six-purchase sequence satisfies the requirements. The total budget alone
does not reveal the intended sequence. Table
[3](#A1.T3 "Table 3 ‣ A.1.1 Shop ‣ A.1 Environment Construction ‣ Appendix A CAMG-II Environment Details ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
lists the eight task families. Later requests can depend on an earlier
choice even when their visible wording and candidate order are
unchanged.

The interaction itself remains WebShop’s native search–browse–purchase
sequence: search\[keywords\], product selection through click\[ASIN\],
inspection of product pages and options, and click\[Buy Now\]. The task
does not disclose which product identifiers constitute the correct
purchase sequence. Each purchase is checked against the task. An
incorrect purchase terminates the episode, retaining earlier earned
rewards but preventing subsequent purchases and the full-sequence
outcome. A correct purchase leads to a continuation boundary before the
next request. Browser state, cart, page trace, and active messages
reset. Customer identity, purchase history, cumulative budget, and the
episode workspace persist. The native success predicate requires the
complete valid sequence. CAMG-II retains CAMG’s 720 verified Shop
products \[[37](#bib.bib37)\].

#### A.1.2 Coding

One Coding episode asks the policy to resolve a SWE-smith issue in a
specified repository revision \[[70](#bib.bib70)\]. Diagnosis, code
edits, and test results can span several context windows. The repository
and episode workspace therefore persist when the active messages are
replaced, allowing later actions to reuse earlier evidence. We draw
issue–repository pairs from CAMG’s executable collection
\[[37](#bib.bib37)\]. An admitted task has a complete issue,
reconstructible repository revision and runtime, an executable hidden
grader, and a reference repair that passes the declared tests. The
policy receives the issue and repository, with ordinary shell access for
inspection, edits, reproduction, and local tests. Hidden evaluation
materials remain outside the acting workspace. The retained collection
contains 11,218 executable tasks from 93 repositories
\[[37](#bib.bib37)\].

An explicit submission ends the repair attempt. An ordinary explanation
does not itself constitute submission. The native shell submission
sentinel is COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT. The grader evaluates
the submitted repository changes against issue and regression tests.
Persisted edits retain the candidate repair across context replacement,
while notes can retain why the repair was chosen, which alternatives
failed, and which tests still need to run. This distinction lets memory
interventions preserve the patch while changing the evidence used to
continue verification.

#### A.1.3 AutoResearch

One AutoResearch episode gives the policy a public OpenMLE task package
containing data, a task description, and a sample submission
\[[71](#bib.bib71)\]. The policy inspects the data, writes and runs
code, and uses public feedback to improve a candidate solution. Earlier
observations, experimental choices, and intermediate results can be
preserved in the workspace across context replacement. A submit action
sends the final submission to the private grader and ends the episode.
We use CAMG’s lightweight OpenMLE packages \[[37](#bib.bib37)\]. A
package contains a task description, public training data, test inputs,
a sample submission, and the native metric. Admission checks nonempty
data, a usable prediction target, compatible submission rows, a
reproducible metric, and a reference pipeline that finishes fitting and
prediction under the runtime limits. Provenance and task-specific
licensing accompany the package. Package variants from the same source
remain one source family.

The policy inspects data, writes and executes model-development code,
and uses public local-validation feedback. One terminal submit action
sends the candidate file to an independent private grader. Private test
labels and grader state are inaccessible to both the acting policy and
its file tools. A well-formed submission and successful code execution
are recorded separately from native-metric improvement over the task’s
baseline. Model code and output files persist. Notes preserve data
problems, attempted features, validation evidence, and reasons for
selecting the final candidate. The retained collection contains 931 task
packages from 804 source families \[[37](#bib.bib37)\].

#### A.1.4 General

General uses the enterprise-task packages within MiMo’s broader General
data release. Each package combines a user request with office documents
and task-specific business systems. Documents can include spreadsheets,
presentations, word-processing files, and PDFs. Task-specific tools
expose simulated enterprise systems backed by task-local state. For
example, an accounting task may require reconciling a controlled
spreadsheet with operational records before explaining a discrepancy.
Other tasks require an authorized system update and subsequent
confirmation.

The agent sees the public workspace and advertised tool schemas. System
databases and verifier materials remain outside that workspace.
Interactions with business state pass through the task’s tools. The
native verifier evaluates the final response, delivered files, and
applicable post-action system state. Required rule checks act as gates,
and graded criteria use the task’s weighted rubric. Text criteria are
judged against task-specific requirements. Full rubric satisfaction
determines native acceptance. Grader credentials and reference material
are evaluator inputs.

Package admission requires resolvable public documents, discoverable
task tools, compatible permissions, and verifier support for every
required rubric criterion. Packages with unsupported agent or vision
criteria are excluded rather than graded on a reduced rubric.
Task-specific read-only restrictions on source documents and business
systems remain in force. Private memory has its own authorized
namespace. Useful memory records source identities, entity mappings,
inclusion rules, units, dates, and unresolved conflicts. A fluent final
answer without that evidence need not satisfy the rubric.

##### Tool-interface correction.

We correct a mismatch in the General adapter between the released tool
schemas and their policy-visible signatures. Query fields can be
individually optional while the implementation still requires at least
one filter. A required-only listing hid these fields and presented
parameterized tools as taking no arguments. General now displays every
declared argument, marks required inputs, and instructs the policy to
include required arguments while selecting optional filters as needed.
For example, cash-movement search exposes its counterparty, date, and
status filters instead of an empty signature. The correction changes
tool descriptions and invocation instructions.

#### A.1.5 Visual

Visual adapts MiMo’s static website tasks. A public brief specifies the
site’s audience, required sections, visual style, and front-end
interactions. The policy creates and revises source files and assets,
produces a static delivery tree with an index.html entry, and can
inspect rendered previews before finishing. Preview images reach the
vision-capable policy as images, rather than as base64 text. Context
replacement preserves the site files but removes earlier visual
observations from active context. The policy can record the inspection
findings it needs for the next revision.

Endpoint evaluation uses the absolute single-site visual-grading path.
MiMo’s group-relative training ranking is a distinct signal and is not
an endpoint score. The published absolute rubric evaluates layout
integrity, typography, color harmony, whitespace, and content richness.
Their mean forms the visual component. The overall score is the equally
weighted mean of this visual component, visible query fulfillment, and
asset quality. The rendering configuration, rubric, and judge are common
across evaluated methods. We report the absolute score as well as task
success under a fixed acceptance threshold $`\theta_{\rm V}`$, selected
on development tasks and held constant across methods and seeds. Empty
or visibly broken pages fail the visual criteria. Functional
requirements not observable from a screenshot require separate declared
checks. A visual score alone does not certify JavaScript behavior.

In the main results the five domains are not reported the same way.
Shop, Coding and AutoResearch are task success rates over the held-out
panels. General is a rate as well, but its success is a judge decision:
the rubric is reduced to accept or reject before the episode is counted.
The Visual column keeps the score itself, multiplied by 100 and averaged
over the whole panel, with an episode that ends without a submission
counting as zero. A visual episode ends with a delivered page that the
rubric grades rather than with a binary outcome, and counting an absent
page as zero keeps the column comparable across policies that finish at
different rates, since a policy cannot gain by being graded only on the
pages it chose to deliver.

Admission checks a complete brief, an executable web runtime, a
renderable delivery format, and an available evaluator. Design
requirements are task inputs, while grader instructions are kept out of
the acting conversation. Memory may retain the requested design system,
which components are implemented, preview findings, and remaining
repairs.

### A.2 Shared Agent Interface

##### File actions.

All five environments retain their native task interactions and expose
the same single filesystem tool, following the minimal, shell-only
interface of mini-swe-agent \[[69](#bib.bib69)\]. bash takes exactly one
parameter, a command string, runs every command from the workspace root,
and can create, inspect, search, modify, and execute files. Multi-line
file content is written with one quoted here-document. At each step, the
policy produces one complete response. The environment executes that
response once and returns an observation, task reward, and terminal
state. Each response is sampled once, executed once, and trained as one
RL step, and it consumes one action slot. A compound shell command
remains one response even when it starts several processes or changes
both task files and memory files.

Each episode receives a fresh private workspace that remains mounted
across policy responses and context replacement. Only regular files
below .agent_memory/ count as policy memory. Repository edits, generated
models, temporary files, and caches are not counted as policy memory. A
rendered preview is an observation, and its useful findings enter memory
only when the policy records them. When one response changes both task
files and memory files, both changes remain part of that response. The
workspace therefore lets the policy preserve information outside the
active context, following the distinction used in language-agent memory
architectures \[[57](#bib.bib57)\].

##### Context replacement.

The environment decides when context pressure or a declared subepisode
boundary triggers a replacement. At that point, the policy must create
or update .agent_memory/CONTINUATION.md through an ordinary filesystem
response. This response consumes one action slot and is sampled and
trained like every other policy response. The environment confirms that
the write succeeded, the target is a nonempty regular file, and its size
remains within the configured byte limit. An invalid write returns an
error and leaves the boundary pending.

After a valid write, the environment replaces the active message history
with the fixed task and tool instructions plus a neutral instruction
naming the continuation path. It does not insert the file contents into
the new context. The workspace remains mounted. The policy can recover
selected information through a later ordinary file read. It may also
maintain other files under .agent_memory/ and refer to them from the
continuation file. The distillation teacher scores the invocation the
student actually produced, so private labels, hidden rubric answers, and
unread workspace contents never enter it.

##### Execution isolation.

Each episode runs in a network-isolated Linux sandbox with a separate
writable root and fixed limits on processes, execution time, output
size, file count, and writable bytes. Public task inputs are mounted
read-only. Private credentials and grader state remain outside the
sandbox. Episode termination removes the writable workspace and
processes owned by that episode.

## Appendix B A Cost Model for Interface Supervision

### B.1 The cost law

Teaching one action takes $`N\propto 1/(Qu)`$ supervised occurrences
while the student rarely emits it, where $`Q`$ is the probability the
student emits it and $`u`$ the teacher’s preference for it. The
derivation starts from two published facts. The per-token reverse-KL
logit gradient has $`\ell_{1}`$ norm equal to twice the teacher–student
log-probability gap times a student-side factor that grows as the
emitted token becomes less likely under the student
\[[51](#bib.bib51)\]. And the student’s deficiency on the teacher’s
support splits into misallocation plus a coverage term $`-\log Q`$,
where $`Q=\sum_{v\in\mathcal{K}}p_{\theta}(v\mid s)`$ is the student’s
mass on the teacher’s top-$`K`$ set $`\mathcal{K}`$, with the coverage
term invisible to the sampled advantage \[[80](#bib.bib80)\].

Definition
[1](#Thmdefinition1 "Definition 1 (Two-token reduction). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
fixes the reduction, Lemma
[1](#Thmlemma1 "Lemma 1 (Per-occurrence movement). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
gives the movement per supervised occurrence, Proposition
[1](#Thmproposition1 "Proposition 1 (Both outcomes teach). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
combines the two sampling outcomes into a drift, Theorem
[1](#Thmtheorem1 "Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
integrates the drift into the cost, Corollary
[1](#Thmcorollary1 "Corollary 1 (Two factors in the rare-action regime). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
reads it as the two-factor law, and Remark
[2](#Thmremark2 "Remark 2 (Extension to the teacher’s support). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
extends the form from one token to the teacher’s top-$`K`$ support.

###### Definition 1 (Two-token reduction).

Fix one prefix $`s`$ and reduce it to two tokens, $`u`$ preferred by the
teacher and $`y`$ not. Write
$`z=\log\frac{p_{\theta}(u\mid s)}{p_{\theta}(y\mid s)}`$ for the
student’s log-odds and $`z^{*}`$ for the teacher’s, so
$`Q=\sigma(z)=p_{\theta}(u\mid s)`$ with initial value $`Q_{0}`$ and
target $`Q^{*}=\sigma(z^{*})`$, and let

|  |  |  |  |
|----|----|----|----|
|  |
``` math
D=\log\frac{q(u\mid s)}{p_{\theta}(u\mid s)},\qquad E=\log\frac{p_{\theta}(y\mid s)}{q(y\mid s)},
``` |  | (5) |

so that $`D`$ is the teacher–student gap on the preferred token, $`E`$
its magnitude on the other, and $`D+E=z^{*}-z`$ at every point. Write
$`u_{0}=D_{0}+E_{0}`$ for the initial value of the gap. Let $`\lambda`$
be the effective logit step per supervised occurrence, let $`N`$ count
supervised occurrences of the prefix’s tokens, not optimizer steps, and
call the token learned once $`z^{*}-z`$ has closed to a fraction
$`\rho`$ of $`u_{0}`$.

The derivation works at the level of this prefix’s logits, not its
parameters: what the parameters couple across prefixes, together with
repeated supervision within a round and the optimizer’s normalized step,
is absorbed into $`\lambda`$, which is not the learning rate. The result
is a proportionality: it fixes which quantities sit in the numerator and
which in the denominator, and $`\lambda`$ only scales it.

###### Lemma 1 (Per-occurrence movement).

One supervised occurrence of a token $`x`$ moves the log-odds $`z`$ by
$`2\lambda A^{\mathrm{OPD}}(s,x)\big(1-p_{\theta}(x\mid s)\big)`$.

###### Proof.

This is the softmax identity of [Shao et al. \[51\]](#bib.bib51) in the
two-token reduction, where $`z`$ is the difference of the two logits and
the update touches only those logits. ∎

Which token the student samples decides the sign of the movement.
Proposition
[1](#Thmproposition1 "Proposition 1 (Both outcomes teach). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
averages the two cases into a contraction on the gap.

###### Proposition 1 (Both outcomes teach).

Sampling $`u`$ gives $`\Delta z=2\lambda D(1-Q)`$. Sampling $`y`$ gives
$`\Delta z=2\lambda EQ`$, because the score of $`y`$ is negative and its
own mass is pushed onto $`u`$. Both outcomes move $`z`$ toward
$`z^{*}`$, and

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\mathbb{E}\big[\Delta D\big]=-\,2\lambda\,Q\,(1-Q)^{2}\,\big(z^{*}-z\big)+O(\lambda^{2}),
``` |  | (6) |

a rate of $`2\lambda Q(1-Q)^{2}`$ times the full log-odds gap. The
relation is first order in the effective logit step, which is the drift
the continuum limit below integrates.

###### Proof.

The $`Q`$ factor on the second outcome appears together with the $`1-Q`$
frequency of that outcome, so the two contributions are of the same
order in $`Q`$, not of the same order in $`D`$. Using
$`\mathrm{d}D/\mathrm{d}z=-(1-Q)`$ and $`\Delta z=2\lambda(1-Q)`$ times
the score of whichever token was sampled (Lemma
[1](#Thmlemma1 "Lemma 1 (Per-occurrence movement). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
gives
([6](#A2.E6 "Equation 6 ‣ Proposition 1 (Both outcomes teach). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")).
Expanding $`D(z+\Delta z)`$ about $`z`$ leaves a second-order term in
$`\lambda`$, which is what the $`O(\lambda^{2})`$ records and what
vanishes when the recursion becomes the differential equation below.
Sampling $`u`$ alone would have given $`2\lambda Q(1-Q)^{2}D`$, which is
slower by the factor $`(D+E)/D`$. ∎

###### Theorem 1 (Cost).

Under Definition
[1](#Thmdefinition1 "Definition 1 (Two-token reduction). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"),
write $`u=z^{*}-z`$ for the gap and let $`N`$ count the supervised
occurrences that close it to the fraction $`\rho`$. Separating variables
in the drift
([6](#A2.E6 "Equation 6 ‣ Proposition 1 (Both outcomes teach). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
gives the exact mean-field cost

|  |  |  |  |
|----|----|----|----|
|  |
``` math
N=\frac{1}{2\lambda}\int_{\rho u_{0}}^{u_{0}}\frac{\mathrm{d}v}{v\,Q(v)\,(1-Q(v))},\qquad Q(v)=\sigma(z^{*}-v),
``` |  | (7) |

from which three statements follow in their own ranges.

While the coverage stays at or below one half along the trajectory the
drift gives the bound

|     |                                               |     |     |
|-----|-----------------------------------------------|-----|-----|
|     |
       ``` math
       N\;\leq\;\frac{\log(1/\rho)}{\lambda\,Q_{0}},
       ```                                            |     | (8) |

which uses only the initial coverage. In the rare-action regime, where
the student rarely emits the token throughout, so that $`Q(v)\ll 1`$ and
$`1-Q(v)\approx 1`$ on the whole interval,

|  |  |  |  |
|----|----|----|----|
|  |
``` math
N=\frac{1+o(1)}{2\lambda\,Q_{0}\,u_{0}},\qquad Q_{0}\to 0\text{ with }Q^{*}\text{ and }\rho\text{ fixed},
``` |  | (9) |

and the gap enters as a factor. When the coverage instead stays near a
constant $`\bar{Q}`$, which is the regime of a student that already
emits the action, the same drift integrates to

|  |  |  |  |
|----|----|----|----|
|  |
``` math
N\;\approx\;\frac{\log(1/\rho)}{2\lambda\,\bar{Q}\,(1-\bar{Q})},
``` |  | (10) |

and $`u_{0}`$ enters only through the starting point, not as a factor.
The two regimes are limits of
([7](#A2.E7 "Equation 7 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")),
not extensions of one another: the second holds for a policy already
close to the teacher, where $`\bar{Q}\approx Q^{*}`$.

###### Proof.

Read
([6](#A2.E6 "Equation 6 ‣ Proposition 1 (Both outcomes teach). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
as a recursion in the log-odds and pass to the continuum: $`N`$ draws
move $`z`$ by

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\frac{\mathrm{d}z}{\mathrm{d}n}=2\lambda\,Q(1-Q)\,(z^{*}-z),\qquad Q=\sigma(z).
``` |  | (11) |

With $`u=z^{*}-z`$ this is
$`\mathrm{d}u/\mathrm{d}n=-2\lambda Q(1-Q)u`$, and separating variables
gives
([7](#A2.E7 "Equation 7 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
directly, without any approximation on $`Q`$.

For
([8](#A2.E8 "Equation 8 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")),
$`Q(1-Q)\geq Q/2`$ while $`Q\leq\tfrac{1}{2}`$, and $`Q`$ is
non-decreasing along the trajectory, so
$`\mathrm{d}z/\mathrm{d}n\geq\lambda Q_{0}(z^{*}-z)`$, which integrates
to the stated bound.

For
([9](#A2.E9 "Equation 9 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")),
the sigmoid identity
$`\big[Q(v)(1-Q(v))\big]^{-1}=e^{v-z^{*}}+2+e^{z^{*}-v}`$ turns
([7](#A2.E7 "Equation 7 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
into

|  |  |  |
|----|----|----|
|  |
``` math
N=\frac{1}{2\lambda}\int_{\rho u_{0}}^{u_{0}}\frac{e^{v-z^{*}}+2+e^{z^{*}-v}}{v}\,\mathrm{d}v,
``` |  |

and the outer two terms stay bounded as $`Q_{0}\to 0`$ while the first
grows, so

|  |  |  |
|----|----|----|
|  |
``` math
N=\frac{e^{-z^{*}}}{2\lambda}\int_{\rho u_{0}}^{u_{0}}\frac{e^{v}}{v}\,\mathrm{d}v\,(1+o(1)).
``` |  |

With $`Q^{*}`$ held fixed and $`Q_{0}\to 0`$, $`u_{0}\to\infty`$ and the
integral is carried by its upper limit, the exponential integral
satisfying
$`\mathrm{Ei}(u_{0})-\mathrm{Ei}(\rho u_{0})=\frac{e^{u_{0}}}{u_{0}}(1+o(1))`$.
Hence

|  |  |  |
|----|----|----|
|  |

because $`e^{u_{0}-z^{*}}=(1-Q_{0})/Q_{0}`$ exactly, the odds ratio of
the two initial probabilities. Dropping the $`1-Q_{0}`$ factor, which
tends to one, leaves
([9](#A2.E9 "Equation 9 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")).

For
([10](#A2.E10 "Equation 10 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")),
$`Q(v)\to\bar{Q}`$ uniformly on $`[\rho u_{0},u_{0}]`$ as the starting

([7](#A2.E7 "Equation 7 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
is $`\big[2\lambda\bar{Q}(1-\bar{Q})v\big]^{-1}`$ to leading order and

###### Corollary 1 (Two factors in the rare-action regime).

In the branch
([9](#A2.E9 "Equation 9 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")),
the cost has *two* factors, and they are the two axes the interface
shares. Coverage $`Q_{0}`$ is how seldom the student emits the action on
its own. The initial gap
$`u_{0}=\operatorname{logit}(Q^{*})-\operatorname{logit}(Q_{0})`$ is how
far the student’s distribution starts from the teacher’s, which sets the
size of the correction the supervision has to deliver. Once the student
emits the action often enough for that branch to end,
([10](#A2.E10 "Equation 10 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
governs the rest of the way and the gap stops multiplying the cost.

The gap is a discrepancy between the two policies, not a measure of how
strongly the teacher prefers the action. A teacher at $`Q^{*}=0.51`$
against a student at $`Q_{0}=0.001`$ has $`u_{0}\approx 6.95`$ while
barely distinguishing the two tokens, and a teacher at $`Q^{*}=0.99`$
against a student at $`Q_{0}=0.98`$ has $`u_{0}\approx 0.70`$ while
preferring one of them decisively. For a fixed relative contraction, a
smaller gap means both a weaker push and less distance to cover, which
is why $`u_{0}`$ leaves the cost altogether in
([10](#A2.E10 "Equation 10 ‣ Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")).
A gap of the other sign, $`Q^{*}<Q_{0}`$, reverses the drift in
([6](#A2.E6 "Equation 6 ‣ Proposition 1 (Both outcomes teach). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
and moves the student away from $`u`$. Whether the teacher prefers the
right action is a separate question, which the two-token dynamics do not
settle and Appendix
[D.3](#A4.SS3 "D.3 Teacher preference over memory content ‣ Appendix D Additional Experiments ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
measures directly.

### B.2 The interface as a design variable

The objective sets the estimator and the teacher is frozen. The one
design variable left is the interface the supervision passes through.
Supervision arrives only inside an intersection: the action must be one
the student emits on its own and one whose consequence the teacher can
judge. Outside it the failures differ in kind (Table
[5](#A2.T5 "Table 5 ‣ B.2 The interface as a design variable ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")):
an action the student never emits (when to call, which key to use) or an
emitted action the teacher scores uninformatively (argument order, a key
schema). An action the student never emits still moves under the drift
of Proposition
[1](#Thmproposition1 "Proposition 1 (Both outcomes teach). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"),
since a sampled alternative pushes probability toward it, but the
teacher then never supervises that action’s own structure or content.
The state axis has already answered the same question. OPD is valid only
when the teacher scores the state the student actually acted in, and
reconstructing that state is what makes compact-memory distillation work
\[[34](#bib.bib34)\]. The interface axis is the one still open.

|----|----|----|
|  |  *teacher prefers it* |  *teacher does not* |
|  *student emits it* |  supervision: the intersection |  excess: negative advantage, growing with the gap |
|  *student does not* |  deficit: no direct supervision of the ungenerated action |  empty: absent from the loss |

Table 5: Interface supervision has four cells. Rows split by whether the
student emits the action, columns by whether the teacher prefers it.
Only the intersection provides direct supervision on the desired action
and its content. Eq.
[12](#A2.E12 "Equation 12 ‣ B.2 The interface as a design variable ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
prices it.

What the intersection constrains is the action, not what is written.
What to retain and what to recover, and when to do either, can all be
behavior neither model has. The intersection is necessary but not
sufficient: the chosen action must also leave state that persists beyond
the active context and can be read back, which is why we do not
supervise ordinary turns of dialogue.

In the rare-action, large-discrepancy regime of Theorem
[1](#Thmtheorem1 "Theorem 1 (Cost). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"),
teaching one action takes

|  |  |  |  |
|----|----|----|----|
|  |
``` math
\underbrace{N}_{\begin{subarray}{c}\text{updates to}\\
\text{learn it}\end{subarray}}\;\propto\;\frac{1}{\underbrace{Q_{0}}_{\text{student emits it}}\;\;\underbrace{u_{0}}_{\text{initial gap}}}.
``` |  | (12) |

The deficit leaves the action itself unsupervised: the sampled advantage
compares the two distributions only where the student went
\[[80](#bib.bib80)\], so an action the student never emits receives no
direct supervision of its own structure or content, only the indirect
movement that Proposition
[1](#Thmproposition1 "Proposition 1 (Both outcomes teach). ‣ B.1 The cost law ‣ Appendix B A Cost Model for Interface Supervision ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
gives it. The excess is destructive: an action the teacher scores below
the student’s own probability receives a negative advantage that grows
as the gap widens. The probability it frees returns to actions the
student already prefers rather than to the one the teacher would have
chosen \[[16](#bib.bib16), [80](#bib.bib80)\]. The empty cell never
enters the loss, so the interface is never learned. A weak or wrong
preference has two causes: a next-token score is myopic about the
outcome even for a capable teacher \[[83](#bib.bib83),
[49](#bib.bib49)\] — hence token-level reweighting (Sec.
[2](#S2 "2 Related Work ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation"))
— and unfamiliarity, the one an interface can remove.

Dedicated memory tools fall outside the intersection twice over. A
protocol call is a handful of tokens in which one error forfeits the
entire action, so every teacher error is expensive. Its correctness also
follows a convention the visible context does not reveal, which is
exactly what a general teacher can be wrong about \[[13](#bib.bib13)\],
so teacher errors are frequent as well. The weighting compounds it:
reverse KL spends its early signal on the tail. The head is already
matched \[[63](#bib.bib63)\], sampled-token objectives give improbable
tokens disproportionate gradient mass \[[51](#bib.bib51)\] (none under a
renormalized top-$`k`$ view \[[22](#bib.bib22)\]), and the teacher’s
least reliable positions receive the most weight.

CAMP-II is built on this. Memory goes through actions the teacher and
the student already perform, so the teacher scores content it can judge.
We transfer the judgment of what to retain. What a harness computes
across calls stays in the harness \[[12](#bib.bib12)\]. The two models
agree on the interface before training starts, because we choose it.

with the clamps and the dual-clip bound as numerical safeguards. A file

current-to-behavior student ratio. The 100 learner rounds consume 6,400
episode exposures, 1,280 per domain under balanced interleaving. These
are exposures, not unique task counts. Failed native tasks remain
training episodes, and infrastructure retries retain their logical task
identity and enter compute accounting.

##### Compute.

Training CAMP-II-4B took about 250 GPU-hours on eight GPUs, four
training the policy, two generating rollouts and two serving the frozen
teacher, across the 100 learner rounds.

##### Conditional objective.

When task rewards are included, GAE runs over the concatenated
sampled-token axis of each trajectory \[[50](#bib.bib50)\]. A call’s
native reward is placed on the final token of its response row, and
preceding tokens receive zero immediate reward. At a row boundary the
recursion continues at the next row’s first sampled-token state,
including across context replacement. Terminal task outcomes are counted
once, and mechanical resets add no token or reward-bearing row. For
token position $`n`$, with $`r_{n}`$ the sparse reward and $`d_{n}`$
indicating trajectory termination, and with the critic fixed during
target computation,

|  |  |  |  |
|----|----|----|----|
|  | $`\displaystyle\delta_{n}`$ | $`\displaystyle=r_{n}+\gamma(1-d_{n})V_{n+1}-V_{n},`$ |  |
|  | $`\displaystyle A_{n}`$ | $`\displaystyle=\delta_{n}+\gamma\lambda(1-d_{n})A_{n+1}.`$ |  |

The return target is $`G_{n}=A_{n}+V_{n}`$ with zero bootstrap at native
terminal and task-budget termination. Task actor advantages are centred
within each route, scaled by a shared factor, and weighted by
valid-token counts so routes carry equal weight; critic returns are
unchanged. Each actor or critic minibatch accumulates its own
microbatches before its optimizer step. These task advantages are
distinct from the detached distillation signal $`A_{i}^{\mathrm{OPD}}`$.
The pure-OPD realization disables the task-reward loss and the learned
critic, so task-return statistics do not enter its actor gradient.

##### Length accounting.

The prompt ceiling is 65,536 tokens and the response ceiling is 32,768
tokens, within a 98,304-token sequence envelope. Declared observation
envelopes are 8,192 tokens for Shop, Coding, and AutoResearch, and
12,288 for General and Visual. Continuation pressure uses a bounded
ordinary-observation allowance of up to 4,096 tokens, or 5,120 on the
larger- observation routes, further limited by available headroom. The
wrapper also reserves the next response, control-message framing, a
bounded continuation write, and one bounded retry. It requests
continuation before that projection reaches the effective prompt
capacity, provided enough actions remain to write, read, and continue.
The request point therefore depends on framing and retry reserves,
rather than a single fixed prompt threshold. Counting uses the actual
chat template and processor-expanded multimodal prompt. Visual previews
remain image inputs for both teacher and student. Base64 image payloads
are never tokenized as ordinary text. Candidate prompt lengths are
checked before serving. Reserving space alone does not guarantee that a
returned observation fits. A response-length cap does not automatically
make a task an infrastructure failure.

If a nonterminal candidate exceeds a hard prompt or sequence ceiling,
the wrapper terminates the episode for context-budget exhaustion without
serving the invalid prompt. It counts as an unsuccessful task-budget
termination, retains earned native rewards and valid sampled actions,
and is not retried or excluded as infrastructure failure. Already
terminal native outcomes are preserved. Budget termination has no future
continuation value. All interfaces follow the same rule.

##### Two file roles, one workspace.

The 8,192-byte continuation limit applies only to the designated file
written before context replacement. Other memory files, such as task
notes, remain freely organized in the persistent workspace within its
native capacity. The policy need not create these notes before writing
the continuation file or derive the continuation file from them. The
wrapper validates the continuation write and clears active context. It
supplies the file path without injecting its contents. The subsequent
policy-authored read consumes an ordinary response. Interface controls
preserve these budgets and state transitions, changing only the declared
memory interface.

## Appendix D Additional Experiments

This appendix reports five measurements of the memory interface that the
experiments in the main text leave out. Three are taken before training,
on how closely the teacher and the student already agree on memory
content, how much correction each interface asks of the student, and
whether the teacher prefers the write that carries the task’s
information. Two come from the trained policy, on whether the memory
behaviour needs the requirement to write at a boundary and on where the
policy writes and reads its state around a replacement.

### D.1 Teacher–student agreement before training

Before any training, the teacher and the student already organize memory
content alike, and they do so most closely under the file interface. To
test whether an interface’s notes fall inside what both models already
represent, we take the initial Qwen3.5-4B checkpoint and compare the
teacher’s and the student’s similarity structure over the notes each
interface writes. Each interface writes its memory in one of three
forms: a file, a stored record for the memory tools, and a context
summary for compaction. We call the text of any of them a note. The
student produces a note by receiving that interface’s prompt with the
call already opened and completing the text, and each interface yields
$`160`$ notes. We compare the two models on *memory-content tokens*, the
tokens of the note body, leaving out the syntax that frames the write,
the wrapper of the call and the labels of its arguments. The frozen
teacher (Qwen3.8-27B) and the student read the identical student-written
sequence. For each note we average the last-layer states of its content
tokens into one vector, and from those vectors we build the teacher’s
and the student’s $`160\times 160`$ cosine-similarity matrices over the
notes. We compare the two matrices by the rank correlation of their
$`12{,}720`$ note pairs.

interface is therefore the one whose representation of the notes the
student already shares: the two checkpoints agree on which notes
resemble which, while under the memory tools and compaction the student
organizes the same content more loosely.

### D.2 Correction induced by each interface

The file interface asks for the least correction of the three, and that
correction is the most independent. We measure the correction as the
norm of the gradient the distillation loss gives the parameters of the
initial checkpoint when the loss is fitted to the notes of one
interface, per supervised token. This probe uses twelve notes per
interface. Applying the loss of Eq.
[4](#S5.E4 "Equation 4 ‣ 5 CAMP-II: File-Memory Distillation ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")
to those notes and restricting it to the memory-content tokens, the
gradient norm is $`0.36`$ for the file interface, $`1.79`$ for the
memory tools and $`1.14`$ for compaction (Fig.
[12](#A4.F12 "Figure 12 ‣ D.2 Correction induced by each interface ‣ Appendix D Additional Experiments ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")a).
The norm tracks the teacher–student probability gap on the same tokens
(Fig.
[12](#A4.F12 "Figure 12 ‣ D.2 Correction induced by each interface ‣ Appendix D Additional Experiments ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation")b),
because the loss weights each token by that gap. On file-interface notes
the teacher’s probability for the student’s own tokens is close to the
student’s, so little correction remains, while under the memory tools
and compaction the gap is about $`1.6`$ times larger than under the file
interface. Per layer the three interfaces follow one profile and differ
only in scale (Fig.

Note-level gradients can also repeat each other, and repeated directions
teach the student little that is new, so the probe measures a second
quantity, how independent they are: for the MLP gate projection of

note-level gradients and take the participation ratio of its spectrum,
which measures how many nearly independent directions the notes move the

### D.3 Teacher preference over memory content

The teacher prefers the write that carries the task’s own information,
and it does so most often under the file interface. We measure the
preference at two granularities, with the whole note and with the
segment of it that carries the task’s information. For each interface we
first pair two notes written by the same writer under that interface for
different task contexts. Under either context’s prefix the note written
for that context carries the task’s information and the other does not,
so the pair isolates whether the content matches the task. We score both
notes under that prefix with the frozen teacher, as the mean
log-probability per memory-content token, and count a decision as
correct when the teacher ranks the matching note above the foreign one.
A teacher that cannot tell the two apart reaches $`0.5`$ by
construction.

Over $`200`$ pairs per interface, which give $`400`$ decisions, the
teacher is correct in 76.5% of decisions for the file interface, 70.0%
for compaction and 63.8% for the memory tools (Fig.

The file interface’s interval meets compaction’s only over a narrow
band, $`[0.720,0.745]`$, just under a third of the width of either
interval. The decisions are also not independent, since every note is
scored in both orders and each decision is made under one of the $`47`$
contexts. Comparing the interfaces over those contexts, the file
interface leads the memory tools by $`11.6`$ points, with a paired
interval of $`[0.029,0.205]`$ and $`31`$ of the $`47`$ contexts in its
favour, and it leads compaction by $`5.9`$ points, with $`27`$ contexts
in its favour and $`17`$ against. The mean margins are $`+0.286`$,
$`+0.271`$ and $`+0.212`$ nats (Fig.

## Appendix E Extended Related Work

This appendix covers families beyond the three surveyed in the main
text. The memory-aware OPD methods compared experimentally are
introduced in Sec.
[6.1](#S6.SS1 "6.1 Experimental Setup ‣ 6 Experiments ‣ Coding Agent Memory Post-Training II:Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via On-Policy Distillation").

##### Context Compression.

What enters the active context can itself be learned, at several
different sites. [Wu et al. \[64\]](#bib.bib64) condense history with an
external summarizer and train the policy to reason over the summaries,
propagating reward across segmented trajectories. A separate compressor
can be distilled from optimized compression guidelines
\[[21](#bib.bib21)\], and a memory-view router can be trained by
supervised distillation followed by grouped GRPO while the acting policy
stays frozen \[[5](#bib.bib5)\]. Cartridges moves the compression into
the key–value cache: corpus-specific caches are trained offline from
synthetic conversations and context distillation with the language model
frozen \[[9](#bib.bib9)\]. CAMP-II keeps memory as ordinary files and
bounds only the continuation file, so compression is one file operation
among others rather than the memory representation itself.

##### Long-Horizon Agent Environments.

These environments provide task feedback over extended agent
interactions: existing benchmarks span heterogeneous interactive tasks
\[[31](#bib.bib31)\], and training frameworks support multi-turn policy
optimization \[[65](#bib.bib65)\]. CAMG-II contributes five
heterogeneous long-horizon environments, including visually grounded web
development, for joint memory post-training through a shared file-memory
interface \[[37](#bib.bib37)\].

##### Experience Reuse.

Experience reuse conditions learning on what earlier episodes produced.
[Zhang et al. \[81\]](#bib.bib81) distill the selection, use, writing,
and maintenance of a hierarchical experience repository, and [Ye et al.
\[77\]](#bib.bib77), [Ye et al. \[76\]](#bib.bib76) condition
distillation on historical solution traces and guiding contexts, with
the latter iterating experience extraction and consolidation. A second
group builds self-teachers from experience: cross-problem behavioral
patterns serve as a memory-conditioned scaffold that is removed at
inference \[[33](#bib.bib33)\], skill-conditioned self-distillation is
gated alongside task RL \[[36](#bib.bib36)\], and hindsight skills are
extracted as the supervising signal \[[72](#bib.bib72)\]. [Wu et al.
\[62\]](#bib.bib62) couple policy updates with an evolving trajectory
analyzer, [Tu et al. \[58\]](#bib.bib58) select the local teaching
direction by comparing skill-conditioned and plain-context returns, and
BCSD augments and prunes explicit skill context to rescale RL
advantages, retaining skill guidance at inference \[[43](#bib.bib43)\].
These memories support reuse and hindsight-guided learning across tasks,
whereas CAMP-II retains only the current episode’s state for continued
execution.

##### On-Policy Distillation.

The design space of OPD \[[1](#bib.bib1)\] extends beyond the memory
setting. The teacher is one design choice: [Zhao et al.
\[85\]](#bib.bib85) construct a self-teacher from privileged information
and fix the initial policy as the teacher, while [Hübotter et al.
\[14\]](#bib.bib14) condition a self-teacher on rich textual feedback or
successful rollouts and use an exponential-moving- average one. [Li et
al. \[29\]](#bib.bib29) analyze the mechanisms and practical recipe of
OPD. Filtered privileged rollouts can be combined with RLVR to address
prompts yielding zero reward \[[8](#bib.bib8)\], and complete student
trajectories can adapt the teacher while prefix-only student inputs are
preserved \[[11](#bib.bib11)\]. The trajectory can also be repaired
before the supervision is applied: unreliable token supervision can be
attributed to failed prefixes and the rollout revised
\[[17](#bib.bib17)\], teacher–student continuation asymmetry can trigger
a short teacher leg \[[67](#bib.bib67)\], and an intervention can be
validated through its effect on the student’s continuation
\[[3](#bib.bib3)\]. The training objective, teacher parameters, and
scoring information are separate design choices. CAMP-II holds the
teacher fixed and varies the training objective within the same
file-memory interface.

##### Token-Level Supervision.

A separate axis within OPD selects which of the tokens already produced
should carry supervision. Privileged action traces can change the
teacher’s input while the student objective still spans responses
\[[44](#bib.bib44)\], and restricting privileged input is a different
choice from restricting the distillation loss to action tokens.
Supervision can vary by within-sequence position \[[32](#bib.bib32)\]. A
teacher-directed perturbation’s first-order effect on the RL surrogate
can redistribute auxiliary-loss mass within a turn \[[25](#bib.bib25)\].
Token selection and privileged-information adjustment can be coupled to
a student learning-difficulty budget \[[73](#bib.bib73)\]. A
reference-only component can be subtracted to construct a
question-conditioned target \[[52](#bib.bib52)\]. Supervision can be
added on aligned final-layer hidden states, projecting the
teacher–student residual through a frozen rank-64 factor estimated from
residual covariance and LM-head Fisher sensitivity \[[4](#bib.bib4)\].
Tutor consensus can admit supervision when no external correctness
labels are available \[[56](#bib.bib56)\]. These approaches select
supervision by reliability, estimated utility, or representation
geometry. A next-token score can be myopic about the outcome even for a
capable teacher \[[83](#bib.bib83), [49](#bib.bib49)\], and the overlap
between the two models predicts whether on-policy sampling helps at all
\[[84](#bib.bib84)\]. Which tokens a memory task produces at all is
decided upstream, by the interface. CAMP-II fixes that upstream choice
and leaves the per-token criterion to these methods.

##### Distillation with Privileged Information.

Teacher supervision often rests on information the student will not have
at deployment. Policy Distillation transfers control policies into a
student \[[48](#bib.bib48)\], and generalized distillation lets the
supervision be computed from training-only privileged information
\[[35](#bib.bib35)\]. In partially observable control, privileged state
supports provably efficient learning under specified structural
assumptions \[[2](#bib.bib2)\], but asymmetry also creates limits: a
teacher’s state-conditioned decision may be unrealizable from the
student’s observations \[[24](#bib.bib24)\], the relative merits of
distillation and direct decision learning depend on the problem class
\[[55](#bib.bib55)\], and [Jiang et al. \[18\]](#bib.bib18) train a
smaller critic to supervise a fixed proprietary actor, so oversight
comes from a model that sees less than the actor rather than one that
sees more. Whether privileged content actually helps admits causal
controls. Replacing a paired solution with another problem’s solution
retains substantial gains, exposing context-induced teacher behavior
\[[15](#bib.bib15)\]. Correct-reference benefits vary with generation
mode, scale, and dataset \[[54](#bib.bib54)\]. Reference value varies
across rollout configurations when multiple reasoning views are compared
with reference-free distillation \[[82](#bib.bib82)\]. Changes in token
likelihood are distinct from changes in expected task outcome
\[[40](#bib.bib40)\]. Self-distillation as a lone objective can show
falling loss without corresponding validation gains
\[[13](#bib.bib13)\]. These findings separate target fit, reference
utility, and deployable task behavior, and CAMP-II measures those links
with content-target probes, memory interventions, and test-set
evaluation. The frozen teacher scores only what the student can see, and
only the student remains afterwards.

##### Agent Distillation.

Agent distillation transfers a teacher’s task-solving capability into a
smaller deployable student. [Kang et al. \[20\]](#bib.bib20) transfer
full task-solving behavior with retrieval and code tools through teacher
trajectories, and [Lyu et al. \[38\]](#bib.bib38) extend the recipe with
student rollouts: behavior cloning of the trajectories first, then
teacher correction and further fine-tuning, then short-horizon RL. At
the inference-time end, Agent Memory Distillation transfers hierarchical
teacher memories through prompting and retrieval without parameter
training \[[23](#bib.bib23)\]. Compact skills summarized from agent
trajectories can serve as dynamic privileged information
\[[59](#bib.bib59)\], and RetireOPD trains a decoupled skill-conditioned
teacher whose supervision is retired once student–teacher discrepancy
and success criteria are met \[[78](#bib.bib78)\]. What transfers is the
teacher’s task behavior, and when its supervision stops is a design
choice. The complementary question in CAMP-II is how the memory
interface affects supervision of the acting policy’s own task-state
records.

##### Behavioral Side Effects of Distillation.

Distillation can change behavior beyond task success.
Sampled-demonstration self-distillation can concentrate correct outputs
and flatten pass@$`k`$ gains \[[41](#bib.bib41)\], and [Peng et al.
\[45\]](#bib.bib45) diagnose thinking collapse through suppression of
epistemic tokens at high-entropy decision points. Self-distillation has
also been studied as a mechanism for continual learning
\[[53](#bib.bib53)\], whereas Denser $`\neq`$ Better finds stronger
forgetting and formatting feedback loops in its tested continual setting
\[[60](#bib.bib60)\]. When Context Returns studies a different failure:
performance can deteriorate when the privileged context is restored, and
no-context anchoring can reduce this harm \[[61](#bib.bib61)\]. Together
these studies motivate measuring reasoning behavior, diversity, and
context sensitivity alongside success. CAMP-II evaluates task success
together with paired content interventions, and leaves these behavioral
measures outside its evaluation.
````
