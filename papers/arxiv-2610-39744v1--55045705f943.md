# PaperBenchX: Can AI Reproduce Science Across Disciplines?

UniPat AI

###### Abstract

Before AI can be trusted to discover new science, it should be able to
reproduce what science already knows. Reproduction provides a rigorous
checkpoint for an AI scientist: the target claim is known, yet
recovering it still requires translating an incomplete scientific
description into an executable experiment and producing evidence that
can be independently verified. Existing research-reproduction benchmarks
largely focus on AI and machine learning, where experiments share
relatively homogeneous software stacks. Extending this capability across
scientific disciplines introduces a different challenge: agents must
operate domain-specific scientific software, make physical and numerical
choices, diagnose long-running computations, and distinguish valid
evidence from merely plausible outputs. We introduce PaperBenchX, a
benchmark of 93 expert-constructed paper-reproduction tasks spanning 12
research areas across electromagnetics, photonics, chemistry, materials
science, biology, and robotics. Each task provides the source paper, a
public task specification, and a domain-native scientific environment
involving specialized scientific software. Agents must reconstruct a key
experiment, execute and diagnose it, and deliver a runnable workflow
that supports the target scientific claim. To evaluate scientific
validity rather than surface-level agreement, we replay every submission
from scratch and score only regenerated evidence against
expert-validated criteria. Across 10 frontier agent configurations, the
best configuration fully reproduces only 14% tasks under the 90%
threshold. Meanwhile, mean rubric scores range from 27.53% to 59.08%,
indicating that substantial partial progress rarely translates into
complete scientific reproduction. These results reveal a large gap
between paper understanding and reliably producing reproducible
scientific evidence.

## 1 Introduction

Reproducibility is one of the defining features of science: a result is
meaningful not only because it has been reported, but because the
assumptions, procedures, and evidence behind it can be reconstructed and
independently examined. For AI systems, this makes reproduction a
demanding test of scientific competence. An agent must go beyond
understanding a paper’s conclusion to recover how the result was
obtained, translate incomplete descriptions into executable procedures,
operate specialized tools, diagnose failures, and determine whether the
resulting evidence actually supports the claim. Existing reproduction
benchmarks largely focus on AI and machine learning, while cross-domain
scientific benchmarks typically isolate only parts of the
workflow ([Starace et al., 2025](#bib.bib22); [Siegel et al.,
2024](#bib.bib21); [Geng et al., 2026](#bib.bib7)). What remains
underexplored is whether an agent can reproduce published experiments
across disciplines, inside the environments native to the underlying
science.

This distinction matters because, outside machine learning, the
environment is not merely infrastructure. It is part of the scientific
problem. Reproducing an antenna result may require constructing and
solving an electromagnetic model in HFSS; reproducing a photonics result
may depend on geometry, boundary conditions, mode extraction, and
convergence behavior in Lumerical or Meep ([Oskooi et al.,
2010](#bib.bib19)); reproducing a chemistry or materials result may
require choosing basis sets, numerical tolerances, or
electronic-structure settings; and reproducing a robotics result may
require executing and validating behavior inside an embodied simulator.
A workflow can run successfully, generate plausible numbers, and still
represent the wrong physical system. Cross-disciplinary scientific
reproduction therefore demands more than writing code that executes.

We identify three coupled challenges. First, scientific reconstruction:
papers are not executable specifications. Agents must translate prose,
equations, figures, and domain conventions into a concrete experiment,
identify the target observable, and resolve modeling choices that are
not fully specified by the task contract. Second, domain-native
execution: agents must operate specialized scientific software, select
appropriate physical and numerical settings, interpret diagnostics, and
determine whether a computation is stable and converged. Third,
scientific verification: matching a reported value is not sufficient.
The result must arise from a valid experimental workflow, and the
evidence supporting it must be independently regenerable. These
challenges separate scientific reproduction from either rerunning
released code or producing a plausible final answer.

To study this setting, we introduce PaperBenchX, a benchmark for
paper-level scientific reproduction across disciplines. It contains 93
expert-constructed tasks spanning 12 research areas across
electromagnetics, photonics, computational chemistry, computational
materials science, computational biology and bioinformatics, and
robotics and embodied AI. The tasks run in 10 domain-native scientific
computing environments, including Ansys HFSS, Ansys Lumerical,
Meep ([Oskooi et al., 2010](#bib.bib19)), PySCF/GPU4PySCF ([Sun et al.,
2026](#bib.bib23)), ABACUS ([Zhou et al., 2025](#bib.bib29)), Quantum
ESPRESSO ([Giannozzi et al., 2009](#bib.bib8)), AutoDock
Vina ([Eberhardt et al., 2021](#bib.bib6)), Habitat ([Savva et al.,
2019](#bib.bib20)), SimplerEnv ([Li et al., 2025](#bib.bib14)), and
AI2-THOR ([Kolve et al., 2017](#bib.bib12)). Each task is centered on a
verifiable scientific claim from a published paper. The agent receives
the paper, a public task specification defining the reproduction scope
and deliverables, and the required scientific environment, but does not
receive the private reference workflow, reference evidence, or
evaluation rubric. Its goal is to reconstruct the experiment and deliver
a runnable workflow that regenerates evidence supporting the target
claim.

PaperBenchX evaluates sustained, end-to-end scientific reproduction
through replay-grounded verification: agents must maintain scientific
intent, computational state, and evidence provenance while
reconstructing experiments, running and diagnosing long-running
simulations, and refining their analyses; after submission, each
workflow is rerun from scratch in a clean environment, and only
regenerated artifacts are scored against expert-validated criteria. This
design distinguishes plausible implementations and successful software
execution from actual reproduction of the target scientific result.
Across 10 frontier agent configurations on the same 93 tasks, the
strongest configuration exceeds the 90% full-reproduction threshold on
only 13 tasks, while 71 tasks are not fully reproduced by any evaluated
configuration; mean rubric scores range from 27.53% to 59.08%. Agents
often make substantial progress in modeling and execution but fail at
scientific validation, revealing a substantial gap between partial
progress and reliably closing the loop from paper understanding to
reproducible scientific evidence.

Our contributions are threefold:

- •
  Cross-disciplinary paper-level reproduction. We introduce 93
  expert-constructed tasks spanning 12 research areas and 10 scientific
  computing environments, each centered on a verifiable claim from a
  published paper.
- •
  Domain-native scientific execution. Rather than reducing scientific
  problems to a common coding interface, PaperBenchX requires agents to
  operate inside the simulators, software stacks, numerical conventions,
  and resource constraints required by the underlying research.
- •
  Replay-grounded scientific verification. We rerun every submitted
  workflow from scratch and score only regenerated evidence against
  expert-validated scientific criteria, distinguishing plausible outputs
  from reproducible scientific results.

### 2.1 Machine-Learning Research and Paper Reproduction

MLAgentBench and RE-Bench evaluate long-horizon machine-learning
experimentation and research engineering, but their objectives are
specified as task-level metric improvement rather than reproduction of
published claims ([Huang et al., 2023](#bib.bib10); [Wijk et al.,
2024](#bib.bib27)). PaperBench and SA-Bench move toward paper-level
evaluation through reproduction or semantic-alignment rubrics ([Starace
et al., 2025](#bib.bib22); [Hu et al., 2026](#bib.bib9)). They establish
that a final metric alone cannot measure fidelity to a paper, but remain
centered on relatively homogeneous machine-learning software stacks
rather than heterogeneous domain-native scientific environments.

### 2.2 Cross-Domain Scientific Benchmarks

Cross-domain benchmarks broaden the scientific scope but generally
isolate only part of the reproduction process. SciCode, DiscoveryBench,
and ScienceAgentBench evaluate scientific coding, hypothesis discovery,
or data analysis, while CORE-Bench recovers results by rerunning
released code ([Tian et al., 2024](#bib.bib25); [Majumder et al.,
2024](#bib.bib15); [Chen et al., 2024](#bib.bib4); [Siegel et al.,
2024](#bib.bib21)). DISCOVERYWORLD evaluates interactive discovery in a
unified virtual world, and NatureBench constructs paper-derived
scientific-ML tasks ([Jansen et al., 2024](#bib.bib11); [Wang et al.,
2026](#bib.bib26)). ScienceIDE most directly evaluates domain-native
scientific execution by placing agents inside production scientific
software, but its tasks concern repository-level repair and
implementation rather than reproduction of a published experiment ([Geng
et al., 2026](#bib.bib7)).

PaperBenchX targets the intersection left open by these benchmarks. It
requires paper-level reproduction of key experiments, executes tasks
inside heterogeneous domain-native scientific environments, and uses
replay-grounded scientific verification. Submitted workflows must run
again from scratch and regenerate evidence that supports the target
claim; neither a plausible final answer nor a completed repository is
sufficient.

summarizes these distinctions.

## 3 The PaperBenchX Benchmark

PaperBenchX evaluates whether an agent can turn a scientific claim into
independently replayable evidence in the domain-native environment
required by the underlying research.
Figure [2](#S1.F2 "Figure 2 ‣ 1 Introduction ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?")
summarizes the complete lifecycle, from the materials provided to the
agent through clean replay and evidence-based scoring. This section
defines the task, describes the benchmark composition and construction
pipeline, and specifies the evaluation protocol.

### 3.1 Task Definition

Each PaperBenchX task is centered on a verifiable scientific claim from
a published scientific paper. As shown in
Figure [2](#S1.F2 "Figure 2 ‣ 1 Introduction ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?"),
the task input has three parts: the paper; a public task specification
defining the scientific scope, target conditions and variants,
observables, required evidence, and delivery interface; and a scientific
computing environment containing the domain-native simulator,
dependencies, data, and allocated resources. The environment is part of
the task definition rather than incidental infrastructure, because model
representations, numerical conventions, execution procedures, and
convergence evidence differ across scientific software.

The agent must submit a runnable package containing all source,
model-building, simulation, post-processing, and analysis code needed
for reproduction, with reproduce.sh as the canonical entry point. During
clean replay, the evaluator refreshes the task container, restores only
the submitted package, runs this entry point, and collects the outputs
regenerated by the workflow. Those outputs, rather than the agent’s
assertions, are scored against a hidden scientific rubric. The private
reference workflow and _reference artifacts_ are never exposed to the
agent. Reference artifacts are expert-generated simulator logs, raw
numerical outputs, convergence records, and derived metrics produced
during task construction; they establish that the task is executable and
ground its expected evidence and scoring criteria. Values reported in
the source paper remain visible, but private tolerances and reference
evidence are withheld. The task therefore tests whether an agent can
construct a scientifically valid and independently replayable procedure,
not whether it can recover a hidden number.

#### Benchmark composition.

PaperBenchX contains 93 paper-reproduction tasks spanning 12 research
areas and 10 domain-native scientific computing environments, with 3,168
scorable criteria. The twelve research areas are radio-frequency
antennas and arrays; radio-frequency metasurfaces and scattering;
radio-frequency filters and frequency-selective surfaces; integrated
photonic devices; photonic crystals and topological photonics; optical
metasurfaces, gratings, and plasmonics; optical computing and signal
processing; optical resonators, filters, and tunable devices;
computational chemistry; computational materials science; computational
biology and bioinformatics; and robotics and embodied AI.

shows the distribution of tasks across these research areas.

The tasks run in ten domain-native scientific computing environments:
Ansys HFSS, Ansys Lumerical, Meep, PySCF/GPU4PySCF, ABACUS, Quantum
ESPRESSO, AutoDock Vina, Habitat, SimplerEnv, and AI2-THOR. The
benchmark draws on 93 distinct source papers from 44 publication venues,
as summarized in

Each task has an execution budget determined by its simulation scale and
resource requirements; agent time limits range from
$`4\text{\,}\mathrm{h}`$ to $`72\text{\,}\mathrm{h}`$, with a median of

#### Release and benchmark integrity.

We release one representative task from each of the twelve research
areas. Nine tasks include complete, redistributable scientific computing
environments; the remaining three rely on commercially licensed
software, for which we release the task specifications and scoring
details but not the corresponding software environments. The remaining
tasks are retained as a hidden evaluation set to reduce test-set
contamination and preserve the benchmark’s validity for evaluating
future agents.

### 3.3 Task Construction Pipeline

The pipeline proceeds in two stages
(Figure [4](#S3.F4 "Figure 4 ‣ 3.2 Task Statistics ‣ 3 The PaperBenchX Benchmark ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?")):
first building a runnable candidate task, and then validating whether it
can be admitted to the benchmark.

Stage 1: Build. Steps 1–2: paper and claim selection. A domain expert
selects a published paper, identifies a scientifically meaningful claim,
and checks that it can be reproduced under the available software,
licensing, compute, and time constraints. The expert then defines the
scientific scope: the target figure or table, model configuration,
experimental conditions and variants, observables, valid methodological
alternatives, and evidence required to support the claim. Steps 3–4:
environment and public contract. The expert provisions the domain-native
scientific environment and writes the public task specification, which
states the scope, required outputs, submission location, and replay
entry point without disclosing the private rubric or reference solution.
Step 5: initial execution check. The expert implements a private
reference workflow and executes it in the assembled environment. This
first execution check verifies that the simulator can be invoked, the
scoped experiment can finish within the resource envelope, and the
required reference artifacts can be generated. A task reaches the
candidate stage only after this end-to-end workflow runs successfully.

Stage 2: Validate and review. Step 6: rubric construction. The expert
converts the evidence requirements into independently scorable rubric
leaves covering model construction, parameter settings, execution,
convergence, post-processing, and claim validation. Each leaf specifies
the evidence needed for credit and its scoring rule, tolerance, and
weight. Step 7: clean reference replay. The private reference workflow
is rerun from a clean copy of the final container through the same
replay interface used for submissions. Unlike the initial check in Step
5, this stricter execution check verifies that the task does not depend
on stale state, undeclared files, or hidden setup; it also confirms that
the expected artifacts can be regenerated under the final resource
limits and consumed by the evaluator. Step 8: calibration checks.
Successful, partially successful, and invalid workflows are scored to
confirm that the rubric awards supported progress, withholds credit for
missing or contradictory evidence, and distinguishes a complete
reproduction from a plausible but scientifically invalid result. Step 9:
independent expert review. Two independent domain experts inspect the
scientific scope, fairness, reproducibility, evidence requirements, and
scoring behavior.

Tasks that fail because of their scope, environment, or reference
workflow are rebuilt from Stage 1. Failures caused by the rubric,
scoring rules, or evaluator return to Step 6. In either case, all
affected downstream execution, calibration, and review checks are
repeated. Only tasks that pass the full pipeline are frozen and admitted
to the benchmark. Across the benchmark, task construction and validation
required more than 1,000 hours of doctoral-level expert work, or
approximately ten hours per task.

### 3.4 Evaluation

Scientific correctness cannot be established from an agent’s final
report. PaperBenchX therefore evaluates each submission through clean
replay, evidence-based grading, and hierarchical scoring. This
evaluation of the agent’s workflow is distinct from the clean
_reference_ replay in Step 7 of task construction, which validates the
benchmark task itself.
Appendix [B](#A2 "Appendix B Evaluation and Verification Protocol ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?")
gives the full protocol.

Clean replay. After delivery, generated outputs and mutable execution
state are removed. The evaluator refreshes the task container, restores
only the agent’s submitted package, and invokes
bash/home/submission/reproduce.sh with private evaluation resources
inaccessible, outbound network disabled, and task-specific resource
limits enforced. Exit status, timing, source hashes, and execution
provenance are recorded independently of the agent’s report. Only
artifacts regenerated by this replay are admissible evidence; a replay
failure is recorded explicitly, and credit remains possible only for
rubric requirements supported by admissible regenerated evidence.

Evidence-based grading. Replay outputs—including simulator logs, raw
numerical arrays, trajectories, convergence records, derived metrics,
and visualizations—are frozen as a read-only evidence set. Every
scientific conclusion must be traceable to this set: a convergence claim
requires a convergence record, and a reported observable requires both
the raw output and the analysis that derives it. Deterministic checks
evaluate directly testable properties such as file schema, units,
numerical consistency, and task-specific tolerances. Requirements that
need domain interpretation are assessed for every evaluated
configuration by the same GPT-5.6-sol scientific rubric evaluator, with
access to the hidden rubric, reference artifacts, and read-only replay
evidence. The agent’s report may locate or explain evidence, but it
cannot instruct the evaluator or replace missing or contradictory
artifacts.

Rubric stages. Each rubric leaf is assigned to _Modeling_ (scientific
models, assumptions, inputs, parameters, and configuration), _Execution_
(domain-native execution, required completion or convergence, artifacts,
and provenance), or _Validation_ (post-processing and quantitative
support for the target claim). Stage scores normalize earned weight by
the total rubric weight within each stage.

Scoring. Let $`s_{i}\in[0,1]`$ be the score of rubric leaf $`i`$ and
$`w_{i}`$ its effective hierarchical weight. The leaves represent
independently assessable scientific requirements, and their effective
weights sum to one. The task score is

|     |     |     |     |
| --- | --- | --- | --- |
|     |

       ``` math
       R=\sum_{i}w_{i}s_{i},\qquad\sum_{i}w_{i}=1.
       ```                                          |     | (1) |

We report performance at both the task-completion level and the
partial-progress level using two metrics:

- •
  _Full rate_, the fraction of tasks with $`R>0.9`$. A score of exactly
  $`0.9`$ does not qualify.
- •
  _Partial score_, the mean of $`R`$ across the shared 93-task result
  set, which captures weighted progress on incomplete long-horizon
  reproductions.

Every configuration is evaluated on the same task set;
experiment-specific fallback and missing-outcome handling is defined in
Section [4.1](#S4.SS1 "4.1 Experimental Setup ‣ 4 Experiments ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?").
A missing artifact affects only the rubric leaves that depend on it,
leaving unrelated verified evidence eligible for credit.

## 4 Experiments

### 4.1 Experimental Setup

#### Models and scaffolds.

We evaluate ten model–scaffold configurations: GPT-6-Astra
(Codex) ([OpenAI, 2026b](#bib.bib18)), Fable 5.1 ([Anthropic,
2026b](#bib.bib3)), Fable 5 ([Anthropic, 2026b](#bib.bib3)),
Opus 5 ([Anthropic, 2026b](#bib.bib3)), GPT-5.6-sol (Codex) ([OpenAI,
2026b](#bib.bib18)), Kimi-K3 ([Moonshot AI, 2026](#bib.bib16)),
Qwen3.8-Max ([Alibaba Cloud, 2026](#bib.bib1)), GLM-5.3 ([Zhipu AI,
2026](#bib.bib28); [Alibaba Cloud, 2026](#bib.bib1)),
DeepSeek-V4.1-Flash ([DeepSeek, 2026](#bib.bib5)), and HY3 ([Tencent,
2026](#bib.bib24)). Tasks are packaged as Harbor environments ([Laude
Institute, 2026](#bib.bib13)). The two GPT models use Codex ([OpenAI,
2026a](#bib.bib17)), while the other eight use Claude Code ([Anthropic,
2026a](#bib.bib2)). All configurations use the maximum available
reasoning setting and receive the same public task materials and shell
access, without access to the private reference workflow or rubric.

#### Evaluation protocol.

All configurations are evaluated on the same 93 tasks. When Fable 5 or
Fable 5.1 refuses a task, the system automatically falls back to Opus 5:
the original refusal is retained for the refusal rate, while the
fallback submission determines the task score. Missing outcomes and
refusals without a valid fallback count as zero. We report the _partial
score_ as the mean rubric score, the _full rate_ as the fraction scoring
strictly above 90%, and the _refusal rate_ from the original model
responses. All available submissions are clean-replayed and graded by
the same GPT-5.6-sol evaluator ([OpenAI, 2026b](#bib.bib18)),
supplemented by deterministic checks.

#### Overall performance.

GPT-6-Astra (Codex) leads with a $`59.08\%`$ partial score and a
$`13.98\%`$ full rate, yet exceeds the $`90\%`$ threshold on only 13 of
93 tasks. Across models, the macro-average partial score is $`49.26\%`$,
whereas the average full rate is only $`8.60\%`$, showing that
substantial partial progress rarely becomes complete reproduction. This
gap is concentrated in scientific validation: average Modeling and
Execution scores reach $`62.73\%`$ and $`61.83\%`$, respectively, while
Validation falls to $`42.91\%`$. Current agents can therefore make
substantial progress in modeling and execution, but reliably reproducing
a paper’s key experimental results and producing a scientific workflow
sufficient to verify them remains difficult.

## 5 Analysis

#### Partial Progress Rarely Composes into Full Reproduction.

Only 80 of 930 outcomes exceed the 90% threshold, and these successes
are concentrated on 22 tasks; 71 tasks are never completed by any
configuration, and 11 of the remaining 22 are completed by at most two.
Figure 
[6](#S5.F6 "Figure 6 ‣ Partial Progress Rarely Composes into Full Reproduction. ‣ 5 Analysis ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?")(a)
localizes this composition gap. Modeling and Execution have median
scores of 73.4% and 73.5%, respectively, whereas Validation has a median
of only 40.0%. Even among the 304 outcomes scoring at least 80% on both
Modeling and Execution, only 53 (17.4%) exceed the full-reproduction
threshold, with a mean Validation score of 58.37%. These results show
that current agents can often reconstruct and execute substantial
portions of a scientific workflow, yet still fail to compose those
partial successes into an end-to-end reproduction that produces credible
evidence and validates the paper’s claims.

#### Interaction Efficiency Varies Substantially Across Agents.

Figure [6](#S5.F6 "Figure 6 ‣ Partial Progress Rarely Composes into Full Reproduction. ‣ 5 Analysis ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?")(b)
compares each configuration’s trimmed mean interaction turns with its
Partial score and finds only a weak negative correlation ($`r=-0.14`$).
Fable 5.1 and Fable 5 average only about 113 turns yet achieve Partial
scores of 58.17% and 57.96%, respectively, close to the 59.08% attained
by GPT-6-Astra with an average of 348.7 turns. By contrast,
DeepSeek-V4.1-Flash averages 372.6 turns but scores only 45.47%. Longer
trajectories do not necessarily improve reproduction and may instead
reflect repeated trial and error, failure recovery, or continued
execution of a mis-specified workflow. These results indicate that
interaction count alone is insufficient to explain reproduction
performance; the accuracy of early-stage decisions may be an important
factor shaping both interaction efficiency and final scores.

#### Upstream Decisions Shape the Value of Execution.

We sample 50 trajectories from each of four models and divide
tool-mediated time into paper reconstruction, implementation, native
execution, diagnosis and tuning, and evidence and replay.
Figure [6](#S5.F6 "Figure 6 ‣ Partial Progress Rarely Composes into Full Reproduction. ‣ 5 Analysis ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?")(c)
shows that native execution accounts for 51.8–63.3% of elapsed time, but
models differ substantially in how effectively they convert it into
valid scientific evidence. Fable 5 allocates 37.1% of its time to paper
reconstruction and implementation, the largest upstream share among the
four models.

The F-stub UWB MIMO antenna task illustrates this pattern. Fable 5
scores 28.9% in 159 turns, versus 27.4% for GPT-6-Astra in 464 turns and
18.1% for HY3 in 390 turns. It completes three antenna variants and
recovers evidence for port reciprocity, radiation patterns, and
diversity gain. This case shows that execution alone is insufficient.
Sound reconstruction, parameter choices, and workflow design shape
whether computation yields verifiable evidence.

#### Final Outputs Alone Cannot Distinguish Scientific Failure Modes.

Failures take two qualitatively different forms. Some workflows execute
successfully but support an incorrect conclusion because of errors in
modes, ports, parameters, mechanism implementation, or result
extraction. On the polarization-insensitive LNOI edge-coupler task,
GPT-6-Astra receives full Execution credit but only 41.9% in Validation.
Similarly, several models complete replayable experiments for the
eight-element smartphone MIMO antenna but fail to reproduce its reported
performance.

Other failures invalidate the evidence itself. Cached results can
prevent verifier-owned replay, privileged test-state information can
invalidate scientific results, and premature termination can leave no
scoreable submission. Final outputs obscure this distinction: one
workflow executes but reaches the wrong conclusion, whereas the other
establishes no trustworthy result.

Final-output agreement is therefore insufficient. By separately scoring
Modeling, Execution, and Validation and checking replay and provenance,
PAPERBENCHX distinguishes experimental-construction errors, incorrect
conclusions, and unverifiable evidence. End-to-end reproduction requires
not only an output, but one produced by a correctly constructed and
independently verifiable scientific workflow.

## 6 Conclusion

PaperBenchX tests whether agents can turn published scientific claims
into executable workflows and independently verifiable evidence. Across
93 tasks in 12 research areas and 10 domain-native environments, we
evaluate 10 frontier agent configurations. The best achieves a
$`59.08\%`$ partial score but only a $`13.98\%`$ full rate; no
configuration reaches full reproduction on 71 tasks. Agents often build
plausible models and run native simulations, but validation remains
their weakest stage, and more interaction does not necessarily improve
performance. These results make scientific reproduction an
evidence-grounded checkpoint for AI scientists and motivate better
diagnosis, provenance, and verification.

#### From contract to evidence leaves.

The hidden rubric used during evaluation converts the public scientific
requirements into independent leaves. Representative leaves check
whether (i) the executed geometry contains the specified six layers and
full-depth air slots (Modeling), (ii) clean replay regenerates genuine
Meep runs, raw arrays, logs, and refinement controls (Execution), and
(iii) power closure, pole fits, mode agreement, and convergence satisfy
the disclosed scientific conditions (Validation). A missing item affects
the leaves that depend on it rather than silently imposing a global
zero.

#### Evaluator policy.

Only evidence regenerated by clean replay is admissible. The evaluator
accepts equivalent documented data layouts and unit conversions, but
does not infer missing units, phase, provenance, or scientific
quantities from a report. Scientific failures receive zero on the
affected leaves; evaluator read or tool failures instead withhold the
judgment for repair and re-evaluation. Each leaf is judged against its
stated requirement without targeting a model-level score.

## Appendix B Evaluation and Verification Protocol

This appendix expands the evaluation protocol in
Section [3.4](#S3.SS4 "3.4 Evaluation ‣ 3 The PaperBenchX Benchmark ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?").

### B.1 Scope, Resources, and Trial Records

#### Evaluation scope.

The benchmark contains 93 tasks and 3,168 scored rubric leaves. All 10
configurations are evaluated on the same 93 tasks, with the fallback and
missing-outcome policy defined in
Section [4.1](#S4.SS1 "4.1 Experimental Setup ‣ 4 Experiments ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?").
The Partial score is the mean task score over this fixed denominator.
The Full rate counts tasks with an aggregate score strictly greater than
$`0.9`$; ties in reported rankings are resolved by competition rank on
unrounded scores.

#### Resource envelopes.

Each task declares CPU, memory, storage, and wall-clock limits
appropriate to its scientific workflow. Across the benchmark, agent time
limits range from 4 to 72 hours, with a median of 7 hours. Clean-replay
and evaluator limits are specified separately from the agent’s
development budget. Exact limits for the twelve public demonstration
tasks appear in
Table [A5](#A1.T5 "Table A5 ‣ A.4 Platforms and Resource Envelopes ‣ Appendix A Task Package, Inventory, and Public Release ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?").

#### Trial records.

Each trial is linked to a task version, agent configuration, submitted
package, replay status, and per-leaf judgments. Agent runtime,
clean-replay runtime, and grading time are recorded separately. Missing
telemetry remains missing rather than being imputed, and infrastructure
failures are distinguished from an agent’s failure to produce an
executable submission.

### B.2 Expert Annotation and Release Review

For each task, a domain expert maps the target claim to its source
passage, figure, or table; fixes the model configuration, experimental
conditions, observables, acceptable methodological alternatives, and
required evidence; and converts these requirements into independently
scorable rubric leaves. The public instruction, addendum, environment,
and starter submission must agree on the task scope and replay
interface. Private reference workflows, reference artifacts, and grading
tolerances are withheld from agents, while values reported in the source
paper remain visible.

The private reference workflow is first executed to establish
feasibility and then rerun from a clean copy of the final environment
through the same entry point used for submissions. Calibration workflows
representing successful, partial, and invalid reproductions are scored
to check that supported progress receives credit and unsupported claims
do not. Two independent domain experts then review the scientific scope,
fairness, reproducibility, evidence requirements, and scoring behavior.
Changes to the task contract, environment, rubric, or evaluator require
the affected downstream checks to be repeated before release.

### B.3 Clean Replay and Evidence Grading

#### Submission snapshot.

The canonical entry point is bash/home/submission/reproduce.sh. After
delivery, the verifier records the submitted source and required inputs,
removes generated outputs and mutable execution state, and reconstructs
the workspace from the submitted package. This prevents cached or
pre-existing result files from being treated as evidence from the
replay.

#### Controlled execution.

The package is executed with private evaluation resources inaccessible,
outbound network access disabled, and task-specific limits enforced.
Exit status, timing, source hashes, and available execution provenance
are recorded. These records establish how an artifact was produced; they
do not by themselves establish that its scientific content is correct.

#### Frozen evidence.

Artifacts regenerated during replay are frozen as a read-only evidence
set. Deterministic checks cover directly testable properties such as
required paths, parseable formats, units, finite values, numerical
consistency, sampling grids, and task-specific tolerances. Simulator
logs, raw arrays, trajectories, convergence records, derived metrics,
and visualizations are admitted only when they can be associated with
the current replay and the relevant task variant.

#### Leaf judgments and aggregation.

Each rubric leaf is graded from its criterion, effective weight,
relevant replay artifacts, and deterministic check results. Requirements
needing domain interpretation are judged by the same GPT-5.6-sol
evaluator used for every reported configuration. Candidate reports may
identify evidence but cannot replace absent or contradictory artifacts.
With leaf score $`s_{i}`$ and effective weight $`w_{i}`$, the task score
is $`R=\sum_{i}w_{i}s_{i}`$, where $`\sum_{i}w_{i}=1`$. A missing
artifact affects only the leaves that depend on it; replay,
infrastructure, and evaluator failures are recorded separately.

### B.4 Regression and Adversarial Checks

Task-specific regression tests implement the calibration step described
in
Section [3.3](#S3.SS3 "3.3 Task Construction Pipeline ‣ 3 The PaperBenchX Benchmark ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?").
They pair valid controls with deliberately corrupted or incomplete
submissions to test whether the evaluator accepts supported evidence,
rejects unsupported claims, and confines a failure to the rubric leaves
that depend on it.
Table [A6](#A2.T6 "Table A6 ‣ B.4 Regression and Adversarial Checks ‣ Appendix B Evaluation and Verification Protocol ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?")
summarizes the principal check families used across the released
verifiers.

| Check family                         | Perturbation and expected behavior                                                                                                                                                                              |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Contract and parser integrity        | Preserve rubric hashes and complete leaf mappings; reject duplicate keys, nonfinite values, and invalid numerical grids while accepting documented equivalent formats.                                          |
| Native evidence and variant identity | Reject incomplete solver logs, mismatched setup names, explicit non-convergence, and copied variant outputs; accept a shared solve only when the task contract permits it and the variants remain identifiable. |
| Evidence boundary                    | Exclude cached outputs and links outside permitted roots; keep private references and evaluator credentials inaccessible; fail closed when network isolation cannot be established.                             |
| Completion and provenance            | Give no completion credit to an empty submission; require delivery records, input hashes, and preprocessing conventions to agree with the task contract.                                                        |
| Local failure accounting             | Corrupt one input, metric, or figure panel and verify that only dependent rubric leaves lose credit.                                                                                                            |
| Interactive-task contract            | Use evaluator-owned episode records and protocol identifiers; do not allow candidate summaries to replace required trajectory or visual evidence.                                                               |

#### Eight-element smartphone MIMO (Task 1-1).

The task requires two independent eight-port HFSS variants and evaluates
geometry, solver provenance and convergence, matching, isolation,
efficiency, ECC, gain, radiation patterns, and surface currents.
GPT-6-Astra scores $`43.5\%`$ in 187 turns; Opus 5 scores $`41.3\%`$ in
450 turns. Both replay native HFSS workflows and recover several
isolation, ECC, gain, and current criteria. Opus 5 additionally records
five and seven adaptive passes, final maximum $`\Delta S`$ values of
0.0063 and 0.0078, and independent meshes exceeding half a million
tetrahedra.

Neither submission reproduces the central four-port matching target.
Reflection minima and the values at 3.45 GHz miss their required
windows, and the baseline and efficiency conditions fail. GPT-6-Astra
also represents a critical length as a reference parameter rather than
using it in the model. Native execution and agreement on secondary
observables therefore do not establish the paper’s impedance and
efficiency claims. DeepSeek-V4.1-Flash provides a complementary
efficiency example: 1,024 turns yield a score of $`15.3\%`$.

#### F-stub UWB MIMO (Task 1-4).

The task evaluates plain, I-stub, and F-stub variants over a 501-point
sweep. As reported in the main text, Fable 5 scores $`28.9\%`$ in 159
turns, compared with $`27.4\%`$ for GPT-6-Astra in 464 turns and
$`18.1\%`$ for HY3 in 390 turns. Fable 5 completes all three native
variants and recovers evidence for port reciprocity, radiation patterns,
and diversity gain, but none of the three submissions reproduces the
principal S-parameter response. This comparison supports the limited
conclusion in
Section [5](#S5 "5 Analysis ‣ PaperBenchX: Can AI Reproduce Science Across Disciplines?"):
more interactions do not necessarily improve reproduction when the model
or parameterization remains incorrect.

#### Polarization-insensitive LNOI edge coupler (Task 4-5).

This workflow spans 39 Lumerical variants: FDE facet modes, TE/TM
Gaussian overlaps, geometry and alignment variants, and EME sweeps over
four coupling lengths. Fable 5.1 scores $`73.1\%`$ in 111 turns,
followed by Fable 5 at $`72.9\%`$ in 212 turns. Fable 5.1, Opus 5, and
GPT-6-Astra each receive full Execution credit, confirming that complete
replay is achievable in this environment.

The remaining errors are scientific. Fable 5.1 exceeds the allowed
dual-tip TE overlap, Fable 5 exceeds the facet-PDL limit, and
GPT-6-Astra obtains an EME800 TM coupling of only 0.0474 despite
complete replay artifacts. Kimi-K3 has the highest Modeling score
($`83.6\%`$), but its EME output is NaN. The traces show why
intermediate checks matter: one facet solve, polarization and
normalization, and one EME case should be validated before the full
sweep. NaNs, missing modes, or incompatible matrix dimensions should
stop downstream aggregation.

#### Synthesis.

The cases explain why Modeling, Execution, and Validation are reported
separately; they are diagnostic examples rather than a cross-task
ranking.
